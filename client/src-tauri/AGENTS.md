# 桌面端协作约定

适用于 `client/src-tauri/`，补充根目录与 `client/` 的 `AGENTS.md`。

阿里云 SDK 预览见 `client/src/features/templates/AGENTS.md`；更新设计见 `docs/client-update-design.md`；更新签名密钥与 Release 附件检查见 `.github/AGENTS.md`。

## 桌面端服务与诊断

- 桌面客户端在设置「通用」页提供「打开调试日志窗口」按钮，与构建期 `IMV_DEBUG` 无关：页面启动后在内存中缓冲最近的环境、未捕获错误、Promise 拒绝、资源与媒体加载失败（含 MediaError 码）、console.error/warn（空内容不转发）、模板预览 SDK 及本地视频诊断，并统一捕获按钮、页签、输入框、选择框、表单提交等控件操作；密码、密钥和凭据值只记录“已隐藏”；每条记录带发生时刻，补发的旧记录按实际时间与原生日志对照。模板预览播放器：SDK 用不挂到文档上的 `<video>`/`<audio>` 播放素材、加载失败时只打印组件编号，且公开 `event$` 只转发 player 类事件，`sdk.ts` 的 `watchSdkMedia` 在加载 SDK 前接管播放器文档的 `createElement`，把每个媒体元素的加载失败（地址、MediaError 码与原因）和 stalled/waiting 写进日志（SDK 清空地址或中止加载引起的 error 不算失败），`watchPlayer` 记录播放状态（stalled 为警告、broken 为错误）、WebGL 渲染上下文丢失与恢复、素材加载 10 秒仍未完成及之后的用时；播放器加载不了的预览视频不再只显示“已就绪”，`TemplatePreview` 按视频序号提示原因并提供「重试预览」（元数据可读不代表 SDK 能播放，如编码或跨域）。AI 资产叠加播放器是跨源沙箱页面，挂载 15 秒未就绪时记录资产、页面是否已加载与地址，旧预览包记录能力不足；更换资产导致同一播放器重新加载时旧握手作废并重新等待就绪。点击按钮后 `lib/diagnostics.ts` 经 `diagnostics_open`（列入 `desktop-commands`，Windows 只对绑定的 localhost 页面开放）打开独立终端，`src-tauri/src/diagnostics.rs` 把缓冲和后续记录经 `diagnostics_log` 写入应用数据目录的 `data/diagnostics.log` 并持续显示；Windows 新建 PowerShell 控制台（按 UTF-8 读取，避免中文乱码），macOS 打开 Terminal，Linux 依次尝试 xdg-terminal-exec、x-terminal-emulator、ptyxis、kgx、gnome-terminal、konsole 等常见终端，并从终端环境里去掉 AppImage 钩子指向包内（`APPDIR`）的 GTK、GIO、GStreamer 路径；都打不开时文件照常写入，设置页显示原因与日志路径。原生收集只在调试模式里生效，启动时不改环境变量、标准错误或浏览器参数：Linux 在点击「打开调试日志窗口」时才把进程标准错误接到管道（只接管一次），读取线程原样写回原标准错误并逐行记为「原生」，本进程此后的输出与之后启动的子进程（如新的 WebKit 网页进程）进入日志，已在运行的网页进程仍写原来的标准错误；不再默认设置 `GST_DEBUG`（需要 GStreamer 警告时由用户自行带该变量启动），终端查看器的标准错误不进日志。Windows 页面以下的问题由 WebView2（Chromium）子进程处理，`diagnostics/webview2.rs` 在宿主进程收集：订阅主窗口的 `ProcessFailed`，记录 GPU、渲染、工具等子进程退出的类型、原因、退出码（附十六进制）与描述；不打开 Chromium 自身的日志：Windows 上 `--enable-logging` 会给 WebView2 进程弹出控制台窗口（关闭它还可能使页面失效），且浏览器参数只能在创建 WebView2 时设置，无法随调试日志窗口按需开启；不修改 wry 默认的浏览器参数。各平台启动时把 Rust panic 记进内存中的原生缓冲（Linux 接管标准错误后改由管道记录，不重复）。打开日志窗口后（不在启动时）环境记录另报告 WebGL 实际使用的显卡与图形后端、devicePixelRatio、CPU 线程数与内存（Chromium 才有），以及 1080p 的 H.264/H.265/VP9/AV1 能否解码、是否走硬件（MediaCapabilities）。卡顿统计同样只在打开日志窗口后进行（`diagnosticsEnabled()`）：`lib/diagnostics.ts` 在主窗口观察主线程长帧（`long-animation-frame`，不支持时退回 `longtask`，WebKitGTK 两者都不支持；同源的 SDK iframe 的长帧也报到主窗口并带脚本归因，来源归为「阿里 SDK」「应用」或主机名，触发方名称去掉方括号里的地址），播放之外超过 300 ms 的逐条记录；`features/templates/playbackStats.ts` 为每次预览播放（SDK 进入 playing 到暂停、播完或损坏，短于 300 ms 不记）写一条流畅度汇总：按 render 事件计的帧率、从开始到结束的最长无新画面间隔与超过 100 ms 的停顿次数、SDK 视频元素的丢帧（`watchSdkMedia` 以弱引用登记的元素的 `getVideoPlaybackQuality`，开始统计之后才建好的元素从零算起）、等待数据次数、期间主线程长帧的次数、阻塞与样式布局绘制时长及耗时最多的三个来源，以及 JS 堆变化（Chromium 才有），帧率低于 20、间隔超过 250 ms 或丢帧超过 5% 记警告；`TemplatePreview` 在应用时间线超过 1.5 秒时记录生成时间线与转场画面、播放器载入各自的用时。同样只在打开日志窗口后：主窗口 `fetch` 被包装（关闭/重置时只在仍是本次替换时恢复），记录请求失败（网络错误与非 2xx，带方法、去掉查询参数的地址、状态码、用时，文本或 JSON 正文的前 200 字）与超过 3 秒的慢请求，主动取消与 Tauri 的 ipc/asset/tauri.localhost 不记录；每分钟记录 JS 堆（Chromium 才有）及较上次的变化、页面元素与 iframe 数量；记录缩放倍数变化、页面转入后台或回到前台、进出全屏与停止调整一秒后的窗口大小；AI 资产播放器就绪超过 3 秒、参数或位置更新到画面（预览页回报 `imv-preview-rendered`）超过 0.5 秒时记录（预览协议没有逐帧回执，定位是否跟得上无法测量）。以下几类记录与其他页面记录一样先进内存缓冲：AI 资产预览页回报的 `imv-preview-error`、本地预览视频每次读回与保存的大小和用时、字效会话实时连接的建立与中断原因（`briefly` 只记错误名与原因，不带调用栈）、本地库失败及连接期间转为失败、中断或取消的任务。连续相同记录只发一次并每 2 秒汇报重复次数；关闭日志窗口不退出客户端。浏览器不显示该入口且不转发日志。
- 桌面端预览媒体服务 `client/src-tauri/src/media_server.rs`：启动时在 `127.0.0.1` 的系统分配端口绑定（失败与 Windows 页面服务一样阻止启动），地址前缀 `http://127.0.0.1:端口/令牌` 经 `preview_media_base` 命令交给前端（`features/templates/mediaServer.ts`），令牌每次启动随机生成。只提供 `/sample/1～3`（内置示例；正式包读内嵌资源、首次请求解压后缓存，开发模式资源不内嵌、改读 `client/public/preview/`）与 `/local/数据文件名`（`preview_videos::open` 只认各槽位元数据当前指向的数据文件，替换或删除后旧地址失效），只接受精确 `127.0.0.1:端口` 主机与 GET/HEAD（另应答 CORS 预检），支持单个字节范围（206/416），带 `Access-Control-Allow-Origin: *`，由固定数量工作线程并发应答。原因：系统 WebKitGTK（Fedora 45 的 2.54）中 IMS SDK 的 `<video>`（preload=metadata）对 blob URL 一直等不到 canplaythrough，SDK 报告在播放、画面却定格，Chromium 里也明显更晚就绪；同一视频走 HTTP 时各平台都正常。浏览器没有该服务，仍用 blob URL。
- Windows 生产页面通过 `src-tauri/src/localhost.rs` 在 `127.0.0.1` 的系统分配端口提供打包资源，窗口使用 `http://localhost:<端口>`，避免 `tauri.localhost` 不满足空 License 的 localhost 预览条件。仅允许对应 Host 的 GET/HEAD，不暴露任意磁盘文件；开发模式与 macOS / Linux 保持原加载方式，只向本次绑定的精确 localhost URL 开放模板、设置存储和内置后端启动命令，不授权其他端口或域名。
- macOS 通过 `client/src-tauri/Info.plist` 设置 `NSAppTransportSecurity.NSAllowsArbitraryLoadsInWebContent=true`，允许 WebView 访问用户设置的 HTTP 后端；Tauri 自动合并到应用包，修改后重新打包生效。

## 客户端自动更新

- 正式客户端更新核心在 `client/src-tauri/src/updates.rs`，Rust 负责检查、镜像下载、签名、资源切换、回退和官方安装器调用；React 只负责状态展示、草稿/请求门禁及恢复位置。Debug 不启用。
- 启动后的自动检查发现新版本时弹出提醒，展示新版本号与更新方式，可直接一键更新或稍后关闭；稍后只作用于本次运行，下次启动仍会提醒。设置中的手动检查不弹窗，更新详情仍在设置「通用」。
- 默认镜像顺序为 `gh-proxy.org`、`ghfast.top`、`ghproxy.net`、`gpp.hydroroll.team`、`ghproxy.hydroroll.team`、GitHub 直连；编译变量 `IMV_UPDATE_MIRRORS` 可覆盖前缀列表，业务 API 地址不能改变更新信任来源。检查更新同时请求全部来源、取最高的有效版本（总耗时受单源 12 秒超时限制），下载按顺序尝试。清单和资产必须校验签名、大小及摘要；新的界面资源下载后只保留当前、上一版与新版，其余资源文件删除。
- 热更新要求实际原生指纹相同且 `client/hot-update-validation.json` 中登记该版本/平台的真实组合验证；未验证或不兼容时完整更新并自动重启，deb 提供下载引导。不能用模拟测试代替真实组合验证。
- 应用前保护全部已挂载工作区草稿、在途请求及本地所有服务的未结束/未知状态任务，等待说明列出阻止更新的会话标题与服务地址；字效工作区挂载时后台同步由工作区负责（跳过 SSE 会话），未挂载时才由更新等待同步当前服务。最终核查加锁期间新业务请求等待解锁而不报错。多实例通过文件锁阻止同时更新；启动时最多等待 10 秒共享锁，更新存储不可用（目录不可写、不支持文件锁或另一实例仍在安装）只关闭本次更新并提示，不阻止启动。热更新保持窗口，页面确认失败约 40 秒内重试，60 秒未确认或启动发现待确认标记则回退；整包安装失败保留已下载安装包供重试并清除恢复位置；保存的恢复信息不包含播放进度和撤销历史。
- `client/src-tauri/update-tools` 是 Rust workspace 成员，供 build.rs 与发版共用；升级官方 updater 时同步检查 Tauri CLI 的版本绑定签名支持。最低 Rust 1.90；保留 Cargo/Bun 锁文件。
- 修改更新功能时运行客户端完整测试/构建、原生测试及 `cargo test --manifest-path client/src-tauri/Cargo.toml -p imv-update-build --locked`；后者需要先冻结安装客户端 Bun 依赖。发布脚本、release-smoke 与 actionlint 同时验证。详细配置与平台验证见 `docs/client-update-design.md`。
