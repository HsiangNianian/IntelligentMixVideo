# IntelligentMixVideo Client

基于 Tauri 2、React、TypeScript、Tailwind CSS 4 和 shadcn/ui。
模板预览继续使用阿里云 AliyunTimelinePlayer 5.2.2；Windows 安装包通过内置回环 HTTP 服务加载页面，使 SDK 识别到 `localhost`。
客户端与服务端使用同一项目版本；发版前统一更新并提交清单和锁文件，操作见[根目录发版说明](../README.md#tag-releases)。
界面直接显示这个版本：窗口标题（浏览器网页标题与桌面原生标题栏）是「IntelligentMixVideo - v版本号」，设置对话框左侧导航栏的左下角也显示版本号，其下一行是构建校验码（构建时从 git 读取的 7 位短提交哈希，工作区有未提交改动时带 `-dirty`，可选中复制，用来核对运行的是哪一版代码；可用环境变量 `IMV_COMMIT` 显式指定，没有 `.git` 的构建环境退到 `GITHUB_SHA`，都没有时显示 unknown）。版本由 Vite 构建时从 `package.json` 注入，不在界面里另写一处，所以发版同步版本后重新构建即可。

## 客户端更新

设置「通用」展示当前界面版本、原生版本和更新状态。正式客户端在启动后、打开设置时自动检查，启动检查发现新版本会弹窗提醒，可以直接一键更新或稍后关闭（下次启动仍会提醒）；点击「一键更新」才下载。兼容并经过验证的界面版本保持窗口打开、短暂刷新；涉及原生变化时显示重启提示并自动安装重启。Linux deb 的完整升级提供下载链接。Debug 和未配置更新公钥的构建不启用更新。

检查更新同时请求以下全部来源并取最高的有效版本；下载按 `gh-proxy.org` → `ghfast.top` → `ghproxy.net` → `gpp.hydroroll.team` → `ghproxy.hydroroll.team` → GitHub 直连顺序尝试，所有来源的清单及自动下载内容都必须通过 Rust 签名与完整性校验；deb 手动下载后，先按界面显示的签名清单摘要核对文件，再安装。应用前等待未保存内容和后台任务结束（等待说明列出阻止更新的会话），可以取消等待；更新后恢复工作区与已保存内容，预览保持暂停。热更新失败自动回退，多实例同时运行时提示关闭其他实例。

更新实现、签名变量/Secret、兼容验证记录及首次安装要求见[客户端更新方案](../docs/client-update-design.md)。发布工具与更新核心均使用 Rust，完整安装复用官方 Tauri 更新插件。测试命令（仓库根目录）：

```sh
cargo test --manifest-path client/src-tauri/Cargo.toml --lib --bin client --locked -- --test-threads=1
cargo test --manifest-path client/src-tauri/Cargo.toml -p imv-update-build --locked
```

第二条包含调用 Bun/Tauri CLI 的签名集成测试，须先在 `client/` 冻结安装依赖。Rust 最低版本为 1.90。

## 开发运行

先按 [服务端说明](../server/README.md) 启动 MySQL 与 API，模板读写都经过服务端。在本目录执行：

```sh
bun install --frozen-lockfile
bun run dev
```

打开 `http://localhost:1420`。API 地址通过 `client/.env` 中的 `VITE_API_URL` 配置，未配置或留空时默认 `http://localhost:20070`。
模板 SDK 使用空 License 的本地预览，页面域名必须是 `localhost`，不能换成 `127.0.0.1` 或局域网 IP；否则 SDK 会显示「license校验失败」，即使外层提示「预览已就绪」。自定义端口时也请使用 `http://localhost:<端口>`。浏览器验收需确认实际视频画面和播放推进，不能只检查就绪提示；官方限制见 [预览组件接入说明](https://help.aliyun.com/zh/ims/developer-reference/access-the-preview-component-web-sdk)。这个要求针对页面地址，视频资源地址不必改成 localhost。
若尚无 `.env`，可复制 `.env.example` 创建；已有文件直接修改，保留示例视频配置。

```dotenv
VITE_API_URL=http://localhost:20070
```

API 使用其他端口时同步修改此地址，填写服务根地址。
客户端配置保存 API 与示例视频地址，数据库连接和密码只放服务端。修改后重启 Vite 并刷新页面；生产使用需重新构建。
避免在 `.env.local` 中重复设置 `VITE_API_URL`，否则会覆盖 `.env` 中的值。

已有远程后端时，直接填写该服务地址，无需再启动本机 MySQL 与 API。浏览器开发版不能读取桌面客户端保存的设置，需在 `client/.env` 中单独配置同一地址；浏览器设置页的临时修改刷新后失效。开发页面请使用 `http://localhost:1420`（或实际启动端口），以匹配后端允许的 localhost 来源。

首页「设置」在普通 Client 中仅保留「通用」页的后端地址与环境信息，不请求模块目录。`IMV_DEBUG=true` 继续提供 Remotion Agent、上海 IMS、切片、ASR 与启动端口等完整模块设置。模块字段来自后端目录，值保存在当前客户端，和构建环境变量分开；桌面本地 JSON 包含明文密钥，浏览器仅当前页面内存保存。已有模块配置保留，实际请求的配置使用规则不变；未保存时沿用服务端环境默认值。协议、范围与联调步骤见 [模块设置说明](src/features/settings/README.md)。

```sh
bun run build
bun run tauri dev
bun run tauri build
```

Windows 安装包仅在本机回环地址绑定系统分配的空闲端口，窗口访问 `http://localhost:<端口>`；退出程序后释放，无需额外启动 Python 或 Vite。API 允许该 localhost 来源的动态端口。
开发模式仍使用 Vite，macOS / Linux 保留原有 Tauri 加载方式。预览仍需要联网下载 SDK、字体和公开视频；空 License 的 localhost 预览保留 SDK 水印。SDK 的渲染授权改为后台请求：渲染引擎不等授权回应就初始化，授权失败、超时（10 秒）或回应不是 JSON 只写调试日志，不阻塞也不影响预览播放。IMS 渲染引擎初始化失败、载入时间线失败或卡住、60 秒仍不能播放或播放中 10 秒不前进时，预览切换到基础视频继续播放并说明原因，只停用 IMS 侧的文字与特效；播放按钮、进度条、时间轴和 AI 资产照常可用；IMS 还在加载时它们由前端时钟驱动，不必等 IMS。
macOS 通过 `src-tauri/Info.plist` 的 `NSAllowsArbitraryLoadsInWebContent` 允许 WebView 访问用户设置的 HTTP 后端；Tauri 自动将该配置合并到应用包，修改后重新打包生效。
前端构建不代表桌面打包或跨平台预览验证通过；各平台仍须检查真实 WebView、首帧和播放。

## 工作室前端

侧边栏「操练场」使用服务端固定样本，只需在左栏的模板列表里选一个模板即可合成：列表可按名称或 styleId 搜索，每行显示封面、名称与 ID 前 8 位，配置无效的模板改为显示警告且不可选；选中后底部显示完整 styleId，可一键复制。当前开放 IP口播，情景展示与新闻体显示待初始化。中间按竖屏比例播放成片，新任务提交或合成期间仍显示的旧成片标为「上一条成片」；右栏显示任务所用模板、用时与任务 ID，并按真实任务阶段显示分段进度与步骤列表，失败原因写在失败的步骤下，IMS 阶段显示「正在 IMS 渲染」，IMS 完成后显示「正在获取成片并转存 ZOS」；每 15 秒自动查询，也可点击「查询进度」立即刷新，查询期间按钮禁用，完成后停止轮询并播放成片；新任务失败保留上一条成功视频。桌面复用本地设置文件保存当前模板、在途任务及最近成片，内置服务重启端口变化仍可恢复；远程服务按地址隔离，浏览器使用 localStorage。切页继续查询并暂停播放，查询断线可手动继续，不重发合成。任务返回 404 时可主动清除失效任务，保留模板选择与最近成片；本地记录读取失败可重试，损坏记录经用户选择后仅重置当前服务的操练场数据。服务端初始化步骤见[视频合成 API](../server/src/server/video_composition/api.md#操练场)。

正式客户端已采用 [PR #196](https://github.com/HsiangNianian/IntelligentMixVideo/pull/196)（`44d5bff`）的工作室设计。运行 `bun run dev` 后直接打开 <http://localhost:1420/>，桌面端运行 `bun run tauri dev`。独立 Demo 入口、模拟数据和原型调试面板已移除。

- `src/components/studio/`：导航、启动动画、模板卡片和对话框等视图组件。
- `src/styles/studio.css`：冷白与深灰两套主题、Geist 字体和靛蓝强调色。
- `src/features/`：真实模板读写、SDK 播放器、AI 会话、参数与资产保存，沿用现有接口。

模板编辑以素材、预览/时间轴、对象参数三栏排布；未打开模板时，提示和「前往主页」按钮在侧栏右侧可用区域水平、垂直居中。素材切换「特效素材 / AI 资产」，Ctrl/Cmd+S 保存当前编辑页。AI 字效采用可收起的历史列表、聊天、预览和模板参数四栏；右上角「保存资产」是唯一的保存入口，保存当前预览版本，按该版本聊天卡片上的分类下拉（默认 Agent 判断的分类）发布，有未保存参数时需先保存配置或撤销；本会话已有资产时旁边的「保存方式」默认覆盖该资产，也可另存为新资产。新建会话保留在历史栏。窄窗口切换聊天/预览，空画布默认竖屏 9:16，已有版本按真实尺寸展示。页面切换保留未保存草稿与会话。 保存处可填写资产名称（去除首尾空白后最多 100 字符）：首次保存留空使用 AI 名称，覆盖或重复保存留空保留资产现名；填写后名称与发布内容一起保存。工作区订阅共享资产目录变化，并在窗口重新聚焦时补读，模板编辑处的重命名立即反映到覆盖选项与名称提示，后台刷新不清除未保存的名称草稿；目录读取失败先重试，不退化为新建。

主页「我的模板」只列出云端模板，标题栏显示数量与刷新入口；读取失败显示原因与重试入口。

模板与 AI 生成都需要可用的后端服务。界面显示实际连接和失败状态。图标与字体出处见 `public/THIRD_PARTY_NOTICES.txt`。

工作室界面保留客户端更新与中英双语模板支持。更新后恢复原工作区和已保存模板；新建、删除等业务弹窗打开时继续等待，关闭后才允许应用更新。

左下角「设置」上方的「主题」按钮切换亮色与暗色，太阳 / 月亮图标表示当前模式；主页、模板编辑、AI 字效、字体库和弹窗同步生效。选择沿用 `localStorage` 的 `imv.theme` 保存，刷新或重启后在首帧前恢复；尚未选择时按系统明暗偏好初始化。存储不可用时仍可切换，但只对当前窗口生效。

## 示例视频配置

在 `client/.env` 中设置：

```dotenv
VITE_PREVIEW_VIDEO_1_URL=https://your-domain.example/preview.mp4
VITE_PREVIEW_VIDEO_2_URL=https://your-domain.example/preview-2.mp4
VITE_PREVIEW_VIDEO_3_URL=https://your-domain.example/preview-3.mp4
```

以上配置分别对应视频 1、视频 2、视频 3，均支持 HTTP(S) 直链和 public 资源路径。例如将视频放入 `client/public/preview-2.mp4`，填写 `VITE_PREVIEW_VIDEO_2_URL=/preview-2.mp4`。
每个地址未配置或留空时使用对应的内置示例：`client/public/preview/` 下随客户端打包的 10 秒片段（1080×1920、30fps、无音轨），桌面客户端经本机的预览媒体服务以 HTTP 地址播放，浏览器首次读取时整段读入内存后播放，不再每次从网络下载。默认来源与弹窗填写的 URL 均由工作区读取真实时长和尺寸，读取失败可以重试，读取完成前不计算预览时间。工作区的预览视频与模板独立，保存模板只保存对象配置和时间规则。

时间输入和开始、持续方式的选择立即更新内存草稿及预览；点击「保存模板」才写入存储。空值或非法时间会提示错误，修正后继续编辑。

时间默认值按 IMS 接口配置：[转场默认 1 秒，文字入场与出场各 0.5 秒](https://help.aliyun.com/zh/ims/developer-reference/effect-configuration-description)；滤镜和 VFX 默认从视频开始持续到结束。切换固定时长时按当前视频剩余区间填写，没有有效区间时等待用户输入；用户已经设置的时长继续保留。

新模板自动创建中文标题和中文字幕各一个。创建和更新时，前端与云端保存都检查中文对象各一个；缺少任意一个便拒绝写入并保留已有记录。通过左侧「特效资产」选择样式，右侧编辑对象参数。
修改后重启 `bun run dev`；生产构建需要重新执行 `bun run build`。
若 `.env.local` 或对应模式的环境文件设置了同名变量，会按 Vite 的优先级覆盖 `.env`。

预览默认使用三个视频，各取前十秒，读取真实媒体信息后播放。点击「加载预览视频」打开弹窗，分别为视频 1、视频 2、视频 3 填写 URL 或点击「本地文件」选择本机视频（每个不超过 512 MiB，可与 URL 混用）；三个来源的真实时长和尺寸全部读取成功、本地文件提交成功后一起更新，再由工作区计算时间区间；读取失败时标明视频编号并保留原有来源，读取期间取消或关闭弹窗会终止读取。每个视频不足十秒时使用完整区间；本地文件不截取，按完整时长排列。画布和 SDK 场景固定为 1080×1920，不随视频尺寸变化；普通预览的视频按 Contain 等比放入，比例不同时用模糊背景填充留白。字号按固定画布像素计算；标题和字幕保留原文，中文交给 SDK 自动换行，不由客户端插入换行。预览按可用宽度和窗口高度的 48% 等比例显示。SDK 在独立 iframe 中加载，更换视频后重新初始化，卸载时释放。视频顺序固定，更换来源后重新计算转场时间，其他对象保留规则。远程直链须允许浏览器跨域读取。本地文件只保存在本机、不上传服务端：桌面客户端把文件复制到应用数据目录的 `data/preview_videos/`（Tauri `preview_video_*` 命令），由预览媒体服务（`src-tauri/src/media_server.rs`，回环地址、随机端口与每次启动的令牌，支持范围请求）以 HTTP 地址播放，视频字节不再经 IPC 读进页面；重启后自动登记并优先于默认地址使用，在弹窗中移除文件并加载即删除本机副本、恢复默认地址；浏览器只在页面内存中使用，刷新后恢复默认。

## 模板行为

标题、字幕设置分别提供「中英双语」复选框。开启后英文作为独立对象出现在画面和时间轴，可单独调整字体、字号、位置或绑定 Remotion 字效；英文标题时间跟随中文标题，英文字幕与中文切片同时出现和消失。示例文字可以编辑，成片由服务端翻译实际文案。关闭后隐藏英文并停止输出，配置和字效绑定随模板保存，重新开启即可恢复；从未开启不创建英文配置。普通英文过长时成片自动缩小字号、尽量保持单行；[Web SDK 暂不支持 AutoScale](https://help.aliyun.com/zh/ims/developer-reference/timeline-support-guide-for-editing-and-previewing-the-component-web-sdk)，预览仍使用设置的字号。Remotion 字效沿用资产的文字长度限制和排版预检，英文标题和字幕的译文过长时优先缩到单行；启用英文字幕时，换行的英文字幕向下展开、中文字幕向上展开，画布空间足够时两条字幕不会互相压住（空间不足或字幕被旋转时仍可能接近），未启用英文字幕时中文字幕保持原本的展开方式。

标题和底部字幕分别提供字体选择：阿里巴巴普惠体、方正仿宋简体、方正黑体简体、方正楷体简体、方正书宋简体、宋体、楷体、微软雅黑、站酷快乐体、思源黑体、思源宋体。字体随各自的 `tracks[].editor.titleFont` / `subtitleFont` 保存为 IMS 标识；预览将 `Source Han Sans CN` 转为 `Source Han Sans CN Normal`，将 `Source Han Serif CN` 转为 `思源宋体`。旧模板缺少字段时采用 `Alibaba PuHuiTi`；重置当前对象时恢复该字体，其他对象的选择保留。共享目录维护在 `server/src/server/template/fonts.json`，`value` 是保存及合成标识，`preview` 是 SDK 标识。

字体下拉框与 Remotion 共用 `features/fonts/FontSelect.tsx` 和 `FontName.tsx`：选项及当前值以对应字体的字形展示名称，下面显示保存标识，支持搜索、键盘选择与主题颜色。IMS 的十一张透明 PNG 保存在 `features/templates/font-previews/`，随客户端打包，浏览字体选项无需下载完整字体。图片由固定 SDK 5.2.2 的对应字体绘制，Remotion 继续使用实时字体库的预览地址和上传功能。

字体预览维护与真实浏览器测试使用 ego-browser。启动 Vite（以下默认 `http://localhost:18766`），测试时还需将 `VITE_API_URL` 指向独立测试后端。通过 `ego-browser nodejs` 在同一个任务中执行下面的代码，`root` 填写本地仓库绝对路径；更新预览图片时调用 `generateFontPreviews`，仅测试时省略该调用。生成函数读取当前固定 SDK 的字体 URL，用浏览器 `FontFace` 和 Canvas 绘制名称，不保存完整字体文件。

```js
const root = "/absolute/path/to/IntelligentMixVideo";
const task = await taskSpace("字体预览验证");
const page = task.page("p1");
const { generateFontPreviews } = await import(root + "/client/scripts/generate-font-previews.mjs");
await generateFontPreviews(root, page);
const { testFontSelect } = await import(root + "/client/tests/font-select.browser.mjs");
await testFontSelect(page);
await task.finish({ keep: [] });
```

IMS 转场时长输入超过 3 秒时立即设为 3 秒，低于 0.1 秒时立即设为 0.1 秒，输入框、滑块和全部 IMS 转场参数同步更新。清空时允许继续编辑，保存前须填写有效时长。Remotion 转场新增时将发布预览长度（`preview_frames / fps`，客户端目录的 `seconds` 同源）写入显式 `duration`，读取、编辑和保存保留其值；已有 `null` 在预览与合成时以发布预览长度为默认值。显式 `duration` 优先，可长于或短于预览长度，预览长度不是业务时长上限。相邻片段过短时按可用长度计算显示区间，保存保留原有时长。

- 资产区按花字、气泡、滤镜、画面特效、转场、入场、出场和循环动画分类，支持名称与编号搜索、分批展示和目录封面预览；缺少封面时显示明确占位。搜索框按 Enter 保留当前编辑。
- 花字和动画通过「应用到」选择文字对象。标题、底部字幕每种语言最多各一个且不可删除，VFX 最多一个；选择样式时保留已有对象的文字、位置与时间。气泡、滤镜可添加多个。文字动画应用到最近选择的文字实例。转场加入统一候选列表，预览在两个视频交界处各选择一个效果，候选数量不限定为两个。
- 前端资产列表排除 `CS0003-000002`；花字下拉框仅在当前对象已使用它时保留该选项及勾选标记，清除或更换后无法重新选择。已有模板仍可读取、预览与保存。
- 右侧「画面对象」列表展示已有 IMS 对象，点击对象打开右侧参数。添加效果统一通过左侧「特效资产」进行，移除对象后也通过资产重新添加，其他对象保持不变。
- 循环动画与入场、出场动画互斥，实际应用时按文字显示时间调整入场和出场时长。每次修改自动应用到 SDK，播放器从下到上叠加视频、滤镜、VFX 和文字。
- 画面下方使用 `@xzdarcy/react-timeline-editor`，从上到下排列标题、字幕、气泡、转场、VFX、滤镜和视频。三个视频各取前 10 秒（用户选择的本地文件使用完整时长），顺序固定，始终每个视频一条 track，视频片段不可拖动和调整长度。初始没有转场，转场共用「镜头转场」一行。其他对象通过右侧设置时间；字幕固定覆盖全程。标题、气泡、VFX、滤镜支持秒数或百分比起点、固定秒数或持续到结束。实例上限为 100。播放位置在 IMS 就绪后由 SDK 推进，降级后由基础视频推进，二者都未就绪时由前端时钟推进；游标与数字时间最多每 0.1 秒移动一次（暂停和播放结束时游标校准到播放器停下的时间）；拖动游标暂停并定位，SDK 确认定位后才可再次点击播放。方向键移动 0.1 秒，Home/End 定位首尾，修改效果后回到开头。
- 缩略图由独立视频元素提取，最多缓存 48 张，卸载或素材变化时取消任务。普通对象保存 `id`、`target`、`start_mode`、`start`、`duration` 和 `editor`；`start_mode` 为 `seconds` 或 `percent`，百分比范围为 0 至小于 100，`duration: null` 表示持续到结束。IMS 转场保存 `id`、`target`、`transition_boundary`、`duration` 和 `editor`，禁止设置 `start`、`start_mode`；Remotion 转场仍使用 Remotion 轨道结构和秒数起点。按这些规则校验，模板不保存 `media`。`resolveTemplate` 根据规则与真实片段生成总长、视频区间、对象区间和提示，预览、时间轴与右侧面板共用结果。预览按 30 FPS 计算帧区间；超过结尾的对象不显示，结束越界时截短，动画按可用帧数缩短并展示说明，帧数不足以表达所选动画时明确报错。
- 选中转场对象或空转场 track 时，右侧显示转场设置；默认及选择其他对象时隐藏。左侧与右侧「＋ 添加转场」均可添加效果，右侧展示全部候选并支持搜索、替换和移除。「使用转场」统一开关通过 `transition_enabled` 保存，默认开启，关闭时保留候选并停止预览及正式合成中的转场；空的「镜头转场」track 始终显示。IMS 统一持续时间为 0.1～3 秒，默认 1 秒，Remotion 使用摆放时长，未指定时以发布预览长度为默认值。「转场选择方式」包括「顺序选择／随机选择」，下方仅提示「预览仅示意效果」：未开启同屏布局、开启转场且存在候选时，预览连接视频 1 → 2 和视频 2 → 3，只有一个候选时两处共用；有多个候选时，顺序选择列表前两项，随机每次从完整候选列表选择，允许连续重复，修改持续时间和其他对象保留本次随机选择。转场按 `transition_boundary` 候选序号排序，删除后连续编号；IMS 与 Remotion 共用列表。`transition_mode=sequence` 在正式合成中按列表循环，`random` 每次从完整候选列表选择，同一候选不限使用次数，任务重试保持选择结果。`transition_duration_seconds` 为 IMS 统一时长。 新合成任务先按口播关键词字幕起点严格寻找前后最近切镜，同刻跳过、去重；有词混剪只找数字人↔素材，纯素材找素材↔素材。首末关键词各保留最近一侧（同距取前，单词及同一切镜只保留一处）；中间从首末关键词起点之间的原候选中随机筛选，最小切镜中心间隔随真实成片总秒数 `T` 取 `min(12, max(4, 8 * sqrt(T / 160)))`，不固定次数。首尾不足间隔时只保留首尾；整片无口播关键词则以全部切镜为候选，同样动态限频，不强制首尾。标题词和英文译文不参与。过短切镜先跳过、不占间隔名额、不找更远处；选点按时间排序后继续按模板分配效果，时长不足不推进顺序候选。同一任务选点与效果可重现，任务 JSON 的 `keyword_transitions` 与 `transition_spacing` 标识保证旧任务按原策略恢复；IMS 与 Remotion 共用逻辑，不新增模型调用或数据库表。完整规则见 [服务端模板说明](../server/README.md#模板接口)。同屏布局预览不应用转场；普通预览转场以视频连接位置为中心，总时长和字幕时间保持不变，保存时才写入模板。
- 居中预览按 30 FPS 计算转场区间；奇数帧时后半段多一帧。三个各 10 秒的视频使用 1 秒转场时，转场位于 9.5～10.5 秒和 19.5～20.5 秒，总长 30 秒。SDK 5.2.2 使用前一段末帧与后一段首帧的图片转场覆盖该区间，补帧位于视频上方、滤镜与文字下方；转场期间使用静帧，SDK 播放与时间轴共用区间。补帧按源地址和采样时间缓存，更换来源或卸载时释放，加载失败显示错误并允许重试。Remotion 转场在同一区间覆盖连续视频。
- 模板保存结构要求 `tracks` 数组，对象参数保存在 `tracks[].editor`。新建草稿自动包含标题和字幕，基础文字无需选择效果即可保存。参数面板使用选中对象的临时视图。前端保存先检查对象时间与文字槽位等规则，云端保存与详情读取校验完整配置；模板列表返回 `TemplateSummary`，无效记录显示 ID 与原因，使用同一垃圾桶入口经确认只删除选定记录。有效模板仍可使用。已有记录不自动转换。列表消息与转场字段需要客户端、服务端一起升级。

- 「蒙版」页签中的「圆形蒙版」卡片描述为“点击添加，开场显示”；点击即启用圆形开场并选中其画面对象，重复点击保留参数。时间轴显示从 0 秒到有效开场结束的“圆形蒙版”片段，点击轨道或对象打开右侧设置，关闭或选择其他对象即隐藏。“移除当前画面对象”关闭开场并移除对象、轨道和设置，保留参数供重新添加，不关闭同屏圆形头像。圆形头像的取景、留量和羽化在“素材与数字人同屏 → 圆形头像”中直接调整，不依赖开场对象；两者共用留量、羽化。右侧选择数字人来源并用「预览取景 X/Y」手动对准源视频中的头部，抠像开关在同屏设置中。示意头部直径固定为源短边 25%，乘留量倍率后裁圆，圆心限制在源内；换视频或数字人来源重置为 50%/50%，来源槽位与取景通过独立的 `avatar_preview` 随模板保存，修改触发未保存状态，重开恢复；不保存媒体地址，也不用于合成，需要客户端与服务端一起升级。成片继续由 OpenCV 自动定位；头像窗口 X/Y 与宽高仍保存并用于成片。开场黑底覆盖素材，结束恢复原素材进度及同屏字幕位置，修改有效参数回到开头并暂停。开场时长、留量或羽化的空值及不符合范围、步长的值只留在输入框并提示，不写入共享草稿；画面对象、时间轴及换视频后的预览沿用有效配置。修正后自动更新，无须重试 SDK。保存按钮、快捷键及名称/描述自动保存都会拦截未完成输入，不能悄悄保存旧值。圆形头像先截取源圆再放进头像窗口，增大留量会缩小圆内人物，不扩大窗口。SDK 与基础播放器共用几何；SDK 只请求 `/template/preview-circle-mask` 几何资源，不传视频或抽帧。

- 旧版本的桌面本地模板保存在应用数据目录的 `data/template/templates.json`（或设置中指定的路径）；当前客户端不再读取、删除或迁移该文件，仍需要的模板请重新创建为云端模板。
- 标题、字幕、气泡独立设置文字、字号、位置、样式、入场/出场/循环动画及动画时长；字号支持 12～300 的整数，预览与云端保存使用相同范围。底部字幕和英文标题仅显示「外观与效果」「关键词设置」页签，中文标题、气泡等对象保留适用的时间页签。
- 顶部标题和底部字幕对象可分别选择关键词局部加粗、斜体、下划线、删除线、颜色和字号；关键词设置页只显示这些样式选项。颜色选择器支持 `#RRGGBB`，关闭后保持文字原色，局部字号支持 12～300 的整数，关闭后沿用原文字号。中文标题预览未指定关键词时从示例标题首段连续文字选取前两个字，英文标题取首个词语，已有指定关键词在标题中首次出现时继续应用；正式合成仅使用 segmentation 返回的 `title_keyword`，缺失或为空时不强调关键词，不回退模板词或标题前两个字。字幕预览选取示例文字的首个词语，正式合成使用切片结果中的 `keyword`。选项保存在 `tracks[].editor` 并随模板返回。
- 画面滤镜、特效、转场和转场时长可选；预览不提交云端合成任务。
- 新模板首次保存创建记录，此后保存更新同一模板；名称和描述跟随当前模板，保存包含全部效果配置。
- 切换前提供保存并切换、放弃修改、取消；失败保留草稿。刷新列表不会覆盖正在编辑的内容。
- SDK 未加载时效果目录使用同版本随包白名单，加载成功后读取 SDK 目录；动画来自静态 `motions.json`；服务端独立校验可信效果 ID。保存必须保留标题和字幕，允许不选择 IMS 效果，可同时添加 Remotion 资产。
- 浏览器关闭或刷新时对未保存修改发出提示；不提供崩溃恢复或定时自动保存；名称、描述修改后的失焦保存沿用上面的完整保存流程。
- 主页列表加载或失败仍允许新建；编辑工作区只读取所选模板详情，保存不依赖列表。尚未保存的新模板同样受切换保护。

## 调试日志窗口

桌面客户端在设置「通用」页提供「打开调试日志窗口」按钮，与构建期 `IMV_DEBUG` 无关：页面启动后在内存中缓冲最近的环境、未捕获错误、Promise 拒绝、资源与媒体加载失败（含 MediaError 码）、console.error/warn（空内容不转发）、模板预览 SDK 及本地视频诊断，并统一捕获按钮、页签、输入框、选择框、表单提交等控件操作；密码、密钥和凭据值只记录“已隐藏”；每条记录带发生时刻，补发的旧记录按实际时间与原生日志对照。模板预览播放器：SDK 用不挂到文档上的 `<video>`/`<audio>` 播放素材、加载失败时只打印组件编号，且公开 `event$` 只转发 player 类事件，`sdk.ts` 的 `watchSdkMedia` 在加载 SDK 前接管播放器文档的 `createElement`，把每个媒体元素的加载失败（地址、MediaError 码与原因）和 stalled/waiting 写进日志（SDK 清空地址或中止加载引起的 error 不算失败），`watchPlayer` 记录播放状态（stalled 为警告、broken 为错误）、WebGL 渲染上下文丢失与恢复、素材加载 10 秒仍未完成及之后的用时；播放器加载不了的预览视频不再只显示“已就绪”，`TemplatePreview` 按视频序号提示原因并提供「重试预览」（元数据可读不代表 SDK 能播放，如编码或跨域）。AI 资产叠加播放器是跨源沙箱页面，挂载 15 秒未就绪时记录资产、页面是否已加载与地址，旧预览包记录能力不足；更换资产导致同一播放器重新加载时旧握手作废并重新等待就绪。点击按钮后 `lib/diagnostics.ts` 经 `diagnostics_open`（列入 `desktop-commands`，Windows 只对绑定的 localhost 页面开放）打开独立终端，`src-tauri/src/diagnostics.rs` 把缓冲和后续记录经 `diagnostics_log` 写入应用数据目录的 `data/diagnostics.log` 并持续显示；Windows 新建 PowerShell 控制台（按 UTF-8 读取，避免中文乱码），macOS 打开 Terminal，Linux 依次尝试 xdg-terminal-exec、x-terminal-emulator、ptyxis、kgx、gnome-terminal、konsole 等常见终端，并从终端环境里去掉 AppImage 钩子指向包内（`APPDIR`）的 GTK、GIO、GStreamer 路径；都打不开时文件照常写入，设置页显示原因与日志路径。原生收集只在调试模式里生效，启动时不改环境变量、标准错误或浏览器参数：Linux 在点击「打开调试日志窗口」时才把进程标准错误接到管道（只接管一次），读取线程原样写回原标准错误并逐行记为「原生」，本进程此后的输出与之后启动的子进程（如新的 WebKit 网页进程）进入日志，已在运行的网页进程仍写原来的标准错误；不再默认设置 `GST_DEBUG`（需要 GStreamer 警告时由用户自行带该变量启动），终端查看器的标准错误不进日志。Windows 页面以下的问题由 WebView2（Chromium）子进程处理，`diagnostics/webview2.rs` 在宿主进程收集：订阅主窗口的 `ProcessFailed`，记录 GPU、渲染、工具等子进程退出的类型、原因、退出码（附十六进制）与描述；不打开 Chromium 自身的日志：Windows 上 `--enable-logging` 会给 WebView2 进程弹出控制台窗口（关闭它还可能使页面失效），且浏览器参数只能在创建 WebView2 时设置，无法随调试日志窗口按需开启；不修改 wry 默认的浏览器参数。各平台启动时把 Rust panic 记进内存中的原生缓冲（Linux 接管标准错误后改由管道记录，不重复）。打开日志窗口后（不在启动时）环境记录另报告 WebGL 实际使用的显卡与图形后端、devicePixelRatio、CPU 线程数与内存（Chromium 才有），以及 1080p 的 H.264/H.265/VP9/AV1 能否解码、是否走硬件（MediaCapabilities）。卡顿统计同样只在打开日志窗口后进行（`diagnosticsEnabled()`）：`lib/diagnostics.ts` 在主窗口观察主线程长帧（`long-animation-frame`，不支持时退回 `longtask`，WebKitGTK 两者都不支持；同源的 SDK iframe 的长帧也报到主窗口并带脚本归因，来源归为「阿里 SDK」「应用」或主机名，触发方名称去掉方括号里的地址），播放之外超过 300 ms 的逐条记录；`features/templates/playbackStats.ts` 为每次预览播放（SDK 进入 playing 到暂停、播完或损坏，短于 300 ms 不记）写一条流畅度汇总：按 render 事件计的帧率、从开始到结束的最长无新画面间隔与超过 100 ms 的停顿次数、SDK 视频元素的丢帧（`watchSdkMedia` 以弱引用登记的元素的 `getVideoPlaybackQuality`，开始统计之后才建好的元素从零算起）、等待数据次数、期间主线程长帧的次数、阻塞与样式布局绘制时长及耗时最多的三个来源，以及 JS 堆变化（Chromium 才有），帧率低于 20、间隔超过 250 ms 或丢帧超过 5% 记警告；`TemplatePreview` 在应用时间线超过 1.5 秒时记录生成时间线与转场画面、播放器载入各自的用时。同样只在打开日志窗口后：主窗口 `fetch` 被包装（关闭/重置时只在仍是本次替换时恢复），记录请求失败（网络错误与非 2xx，带方法、去掉查询参数的地址、状态码、用时，文本或 JSON 正文的前 200 字）与超过 3 秒的慢请求，主动取消与 Tauri 的 ipc/asset/tauri.localhost 不记录；每分钟记录 JS 堆（Chromium 才有）及较上次的变化、页面元素与 iframe 数量；记录缩放倍数变化、页面转入后台或回到前台、进出全屏与停止调整一秒后的窗口大小；AI 资产播放器就绪超过 3 秒、参数或位置更新到画面（预览页回报 `imv-preview-rendered`）超过 0.5 秒时记录（预览协议没有逐帧回执，定位是否跟得上无法测量）。以下几类记录与其他页面记录一样先进内存缓冲：AI 资产预览页回报的 `imv-preview-error`、本地预览视频每次读回与保存的大小和用时、字效会话实时连接的建立与中断原因（`briefly` 只记错误名与原因，不带调用栈）、本地库失败及连接期间转为失败、中断或取消的任务。连续相同记录只发一次并每 2 秒汇报重复次数；关闭日志窗口不退出客户端。浏览器不显示该入口且不转发日志。

## 桌面端预览媒体服务

桌面端预览媒体服务 `client/src-tauri/src/media_server.rs`：启动时在 `127.0.0.1` 的系统分配端口绑定（失败与 Windows 页面服务一样阻止启动），地址前缀 `http://127.0.0.1:端口/令牌` 经 `preview_media_base` 命令交给前端（`features/templates/mediaServer.ts`），令牌每次启动随机生成。只提供 `/sample/1～3`（内置示例；正式包读内嵌资源、首次请求解压后缓存，开发模式资源不内嵌、改读 `client/public/preview/`）与 `/local/数据文件名`（`preview_videos::open` 只认各槽位元数据当前指向的数据文件，替换或删除后旧地址失效），只接受精确 `127.0.0.1:端口` 主机与 GET/HEAD（另应答 CORS 预检），支持单个字节范围（206/416），带 `Access-Control-Allow-Origin: *`，由固定数量工作线程并发应答。原因：系统 WebKitGTK（Fedora 45 的 2.54）中 IMS SDK 的 `<video>`（preload=metadata）对 blob URL 一直等不到 canplaythrough，SDK 报告在播放、画面却定格，Chromium 里也明显更晚就绪；同一视频走 HTTP 时各平台都正常。浏览器没有该服务，仍用 blob URL。

## 字体库页面

左侧导航有「字体库」页面（`features/fonts/FontLibrary`，只在当前页签挂载、每次打开重新读取）：卡片展示库内全部字体卡片（预览条、家族名、风格、来源、已有字形、大小），点击打开字体详情（`FontDetails`：四个字形各自的预览条、字重、大小与 SHA-256，缺少的标为未上传，以及家族名、来源与许可证；点击已有的字形在对话框里打开它的字样 `FontSpecimen`：浏览器经 `file_url` 读取该字形的字体文件、以临时家族名注册为 `FontFace`，排出标题、字母数字、中文与可改示例句的字号阶梯，离开时移除；系统默认字体的文件是服务端安装的常规字重，同样经 `GET /api/templates/fonts/{id}` 提供，本机没有安装时为 null、不打开字样），可按名称或风格搜索，也可在页面上传字体，下拉选择器与该页面共用 `useFonts`（上传前按 SHA-256 在已读到的字体库里查找，已有同一个文件就直接选用、不再上传；修复前的原文件已登记时也不上传修复版，避免同一字体出现两张卡片；请求失败后重新读取字体库，按摘要找到即视为已在库里，因为超时或断线时服务端可能已经登记；服务端回答 200 时提示「字体已在字体库里」而不是「已添加」；不在安全上下文的网页没有摘要能力，只能依赖服务端的幂等回答）。上传前浏览器先做目录级修复（`features/fonts/repair.ts`：只在目录里确实有长度为 0 的可选表时重写，删除这些表、按标签重排表目录并补正二分查找字段、按实际数据重算各表校验和与 `head` 的 checkSumAdjustment、裁掉尾部不属于任何表的字节，字形、name、cmap 等表的数据不动，修复幂等；没有零长度表时保持原字节，避免仅因头部、校验和或尾部字节不整齐就改变摘要），摘要、预览条与上传都用修复后的字节，按内容去重与之后渲染沙箱读到的文件一致；目录或表超出文件末尾、表和表目录或两张非空表重叠、必需表为空、没有可用的轮廓表、`loca` 的偏移不是从 0 开始递增或与 `glyf` 不自洽时拒绝并说明是哪张表，修复后浏览器仍解不开时说明浏览器无法解码，两种都不发上传请求；修复过文件的成功提示写明修了什么。后端不参与修复，仍只读取 name 表。前端 `ParameterControl` 对名为 `fontFamily` 的参数使用 `features/fonts/FontPicker`：读取实时字体库，选项用服务端预览条（CSS mask 着色）展示，可搜索，底部可上传自己的字体并立即选中，聊天参数面板与模板编辑的「外观与位置」共用。

## 开发结构

```text
src/
  main.tsx                         # React 挂载与全局样式
  App.tsx                          # 页面组合
  pages/HomePage.tsx                # 导航与各工作区挂载、切换
  features/templates/
    TemplateHome.tsx               # 主页云端模板列表和选择入口
    TemplateWorkspace.tsx          # 目标详情、草稿、保存及切换保护
    EffectAssets.tsx               # 资产浏览、应用和已添加对象列表
    EffectEditor.tsx               # 当前 IMS 对象的文字、样式与动画设置
    effects.ts                     # 资产字段分配、互斥与移除规则
    TemplatePreview.tsx            # 播放器生命周期及预览操作
    model.ts                       # 数据类型、默认配置与选择字段映射
    api.ts                         # 云端 Protobuf 请求/JSON 响应（兼容旧二进制响应）和模板错误处理
    sdk.ts                         # SDK 加载、目录及类型边界
    timeline.ts                    # 配置到预览时间线的转换
    motions.json                   # 固定版本动画目录
  components/ui/                   # shadcn/ui 基础控件
  generated/imv/template/v1/       # Buf 生成的 Protobuf 消息类型
  lib/utils.ts                     # cn 类名合并
  styles/globals.css               # Tailwind 与语义主题令牌
```

页面 → 功能模块 → 基础 UI / 工具；`@/` 指向 `src/`。不在基础控件中请求 API 或调用 SDK。
SDK 调整时同步核对前端动画目录与服务端白名单。预览时间线每次修改回到开头，快速修改合并后串行应用；只有 SDK 发出 canplay 才显示“预览已就绪”并改由 SDK 推进播放；载入时间线失败或 60 秒没有完成、载入完成后再等满 60 秒仍没有 canplay、定位 10 秒未获确认、播放中 10 秒不前进或渲染失败时切换基础视频并停用 IMS 文字与特效，播放按钮、进度条与时间轴改为控制基础视频；IMS 加载期间（或基础视频还没就绪时）由前端时钟推进播放位置，这些控件与 AI 资产照常可用，IMS、基础视频与前端时钟交接时接着当前位置播放；更换预览视频则回到开头并暂停。预览标题栏的「刷新预览」在加载、卡住或失败时都可用，点击后销毁当前播放器并按当前草稿重新初始化。

shadcn/ui 按实际需要引入并保留第三方声明，许可位于 `public/THIRD_PARTY_NOTICES.txt`。

覆盖 AI 资产会保留已有模板所依赖的参数契约：删除参数、收紧范围等不兼容变化须另存为新资产。目录中的来源版本改变后，资产封面与已打开模板的叠加预览自动重新加载并恢复摆放参数和时间，改名不重载。

`preview-canvas.test.ts` 检查横屏、竖屏、方形和超宽视频均使用固定 1080×1920 画布，以及留白填充、文字参数、SDK 绘制倍数和三个各十秒的默认片段。
画布的真实浏览器回归执行 `bun tests/preview-canvas.browser.mjs`，需要 Chrome、FFmpeg 和联网访问 SDK、字体。脚本自动启动独立 Vite 服务，生成本地视频，验证 Canvas 像素、横竖屏切换、实际播放、数字时间与时间轴游标的更新频率、暂停和播放结束后游标与播放器时间一致、窄屏比例、全屏时 AI 资产叠加层与播放器画面同框（竖屏视频在横屏屏幕上全屏，字效不按整个屏幕放大）、标题和字幕原文与卸载清理；不访问业务后端。中间文件保存在已忽略的 `node_modules/.cache/preview-canvas-tests/`，结束时关闭浏览器和测试服务。
播放器调试日志的真实浏览器回归执行 `bun tests/preview-diagnostics.browser.mjs`，同样需要 Chrome、FFmpeg 和联网访问 SDK、字体。脚本在页面里伪装桌面端接收日志，验证元数据可读但播放器加载不了的视频在预览里按序号提示并把地址与 MediaError 码写进日志，正常视频播放后记录播放状态与流畅度汇总且不误报；中间文件保存在 `node_modules/.cache/preview-diagnostics-tests/`。
`effect-tracks.test.ts` 覆盖独立对象增删、时间规则、视频替换、动画帧数、SDK 数据转换和序列化；`track-timing.test.tsx` 验证输入自动更新、单位换算、非法输入恢复和对象切换。前后端共同使用 `server/tests/template_timing_cases.json` 和 `server/tests/template_sequence_cases.json`，后者覆盖累计重叠、短视频、固定语音时间、转场缩短与缺失交界处；预期结果包含区间和提示，并检查计算过程保留原始规则。

服务端核心验证执行 `uv run --locked --project server pytest server/tests/test_template_tracks.py server/tests/test_template_protobuf.py server/tests/test_template_validation.py server/tests/test_video_composition_timeline.py`（仓库根目录）。现有文案合成按成片时长应用每个对象：标题使用请求文字，字幕及关键词与文案时间取交集，重复实例保留独立参数；新任务保留关键词首尾近侧并按动态间隔随机选择中间转场，旧任务按保存的策略恢复，音频总长保持不变。通过 `TMPDIR` 和 pytest 的 `--basetemp` 将中间文件指向已忽略的缓存目录。
`server/tests/test_template_tracks.py` 直接校验 Schema、默认参数、时间计算和序列化；`test_video_composition_timeline.py` 检查对象规则生成的合成时间线。
工作区测试使用真实表单、Radix 选择器和弹窗，覆盖核心编辑与草稿保护。Happy DOM 无法验证真实视频播放和 Tauri 原生行为。
Happy DOM 的小数 step 校验与浏览器不同，保存流程直接触发表单提交；浏览器原生表单约束仍需浏览器验证。
Windows 原生资源服务的回归测试位于 `src-tauri/src/localhost.rs`，执行 `cargo test --manifest-path src-tauri/Cargo.toml --lib --locked`，覆盖真实 HTTP 资源响应、查询参数、HEAD、错误主机与方法；原生检查 CI 同步执行。

云端模板通过上游 `text_target`／`transition_boundary` 保存 Remotion 文字及转场绑定，兼容旧 `businessTarget` 字段，不额外增加用途控件。旧用途读取与保存时不自动补新槽位，保留 IMS 与 Remotion 共存；右侧说明当前显示方式，用户显式重选作用对象后才采用新槽位。编辑预览与时间轴沿用 upstream/dev 的对象槽位流程，不调用业务输入接口、不等待动态绘制回执。详见 [Remotion 视频合成适配](../docs/remotion-video-composition.md)。
