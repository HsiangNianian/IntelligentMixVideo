# 字效工作区协作约定

适用于 `client/src/features/remotion_templates/`，补充根目录与 `client/` 的 `AGENTS.md`。

服务端字效生成、发布与渲染见 `server/src/server/remotion_templates/AGENTS.md`。

- 字效客户端位于 `client/src/features/remotion_templates/`，说明维护在该目录 README；复用 `VITE_API_URL`，请求前缀为 `/api/templates`，保留原模板库入口。
- 成功版本代码卡片展开时读取 `GET /api/templates/versions/{id}/diagnostics`，按行标注 error/warning 并提供可跳转的诊断清单；高亮由 `codeHighlight.ts` 的展示用近似分词产生，只影响阅读颜色，不参与验收、不进入隔离预览。诊断由服务端在隔离 worker 内重跑，读取失败只降级诊断区并提供显式重试，禁用状态下不发起请求。
- 顶栏「保存资产」的保存处可填写资产名称（去除首尾空白后最多 100 字符）：首次保存留空使用 AI 名称，覆盖或重复保存留空保留资产现名；填写后名称与发布内容一起保存。工作区订阅共享资产目录变化，并在窗口重新聚焦时补读，模板编辑处的重命名立即反映到覆盖选项与名称提示，后台刷新不清除未保存的名称草稿；目录读取失败先重试，不退化为新建。
- 聊天参数面板对文字组合的字效分为「文字」「特效」两块（`model.ts` 的 `textSections`）：「文字」是文字本身的内容、字号、字体、排版、绑定在各栏上的外观、关键词选项与各栏内部参数（「正文」「上栏」「下栏」）；「特效」每个特效一张卡片，标题旁开关决定是否应用，卡片里是位置、时长、绑定在该特效上的样式与它的内部参数，关键词字效（开关 `keywordEffect`）也是一张卡片；其他版本仍分「配置」「样式」（`CONFIG_PARAMETERS`）；模板编辑开放其中的排版参数与特效的开关、位置与时长（「外观与位置」里单列「特效」；不含文字、关键词字效开关，关键词参数在「关键词设置」页签），特效自己的外观属于样式、在字效工作区修改。
- 字效新会话支持生成前选择画布、时长及高级宽高/帧率，默认 1080×1920、30 FPS、5 秒（界面称「预览时长」：只决定生成与预览的长度，最终时长由总线渲染请求的 time 决定）；秒数四舍五入到整帧，至少一帧且不超过 30 秒，尺寸遵循服务端边界。首次请求显式携带 composition，「关键词字效」「双栏」开关打开时另带 `keyword_effect: true`、`two_tier: true`（关闭不携带），非法草稿禁止发送，上传与生成期间锁定；创建后不修改该会话配置，新增恢复默认，历史展示成功版本实际配置，不宣称代码已支持任意规格适配。
- 最左侧历史会话列表顶部提供“新增聊天”，中间聊天，右侧上方预览、下方参数。桌面三栏可拖拽或键盘调宽，本地保存尺寸并提供恢复布局；窄屏使用历史抽屉与聊天/预览切换。成功版本在对应聊天结果下显示默认折叠的代码卡片，可独立复制 Export.tsx、单击预览；参数修订标注来源，失败候选与纯问答不产生版本卡片。历史预览只读，不回滚服务端或改变编辑基线；返回最新才能调参与发送，SSE 新成功版本不抢走明确选中的历史预览，切换旧版本沿用未保存参数的保存/放弃/取消保护。
- 预览背景可用视频直链或「加载本地文件」（仅页面内 blob URL，不上传、不保存，换背景或卸载时释放），不发送模型、不嵌入字效导出。背景由客户端底层 `<video>` 先读元数据再静音循环播放（WebKitGTK 直接自动播放较大 blob 会解码失败），与字效播放独立、不锁定字效操作；版本预览以 `overlay=true` 透明叠加，仍向封存播放器包发送空 `background`。生成、参数保存检查和预览首帧期间，禁用发送、图片变更与参数控件；聊天文字可保留草稿，正常播放不锁定。本地参数草稿实时预览不锁控件、不自动提交；显式保存批量提交净变化，撤销恢复上次成功默认值。未保存时禁止发送、图片变更及复制代码。
- Player 包和带默认 props 的 `Export.tsx` 在服务端隔离构建并纳入产物清单。预览使用无同源权限的 sandbox iframe，消息检查来源、通道和请求编号；完成、失败、超时及卸载均清理加载锁和资源。
- 任务提交使用 POST，公开消息、任务状态与成功版本指针通过作品级 SSE 更新，禁止恢复客户端任务轮询。
- 新增打开空白会话，历史切换、新增、断线和卸载均不取消后台任务；明确停止或确认删除会话才取消。新增或切换历史遇到未保存参数时，提供保存并切换、放弃修改并切换、取消；保存并取得成功版本后才切换，失败留在原会话。迟到结果不得跨会话回填，网络错误不自动重复写入。参数保存失败保留此前成功代码与本地草稿，显式撤销才恢复默认参数。新版本产物读取失败独立提示并提供只读重试，保留旧结果可用性，不能阻塞后续 SSE 或反复重放同一个失败事件。
- 参数未保存、提交中或读取中禁止普通恢复操作，UI 与会话 hook 同时守卫；本次保存响应未知或产物读取失败时允许只读恢复，不自动重发写入。保存绑定当前成功版本，只提交净变化；同一会话重复选择不清空草稿，StrictMode 重建订阅仍须恢复历史。
- 字效会话通过 `DELETE /api/templates/works/{id}` 整条删除，完成或不存在返回 204。先持久化删除标记，取消并等待运行任务及队列收尾，再删除任务草稿与审计、所有成功版本对象与缓存（ZOS 上的对象默认保留，见 `ZOS_DELETE_OBJECTS`）、无其他会话引用的参考图（作品原图和后续消息附图）和关联 MySQL 记录；不删除其他会话或已发布资产，客户端随后删除本地记录。清理失败返回 503（说明为「会话数据清理未完成，请重试删除。」，根因写服务端日志 `Work deletion is incomplete`），保留标记支持显式重试和启动恢复；删除中读写返回 410；客户端收到 404/410 时把本地记录标为 `deleting`，侧栏显示「已删除或正在清理 · 可重试删除」且不能再打开，重试删除成功后才删除本地记录；客户端删除请求最长等待 120 秒（`DELETE_TIMEOUT_MS`），失败提示附上具体原因。已有 SSE 发送无 ID 的 `work.deleted` 控制事件后关闭，404/410 均终止客户端重连。删除确认允许放弃当前草稿，当前会话删除后释放预览与订阅，其他会话删除不影响当前编辑；写请求不自动重发。
- 字效聊天每条消息最多附 4 张参考图（点击选择、拖入或 Ctrl/⌘+V 粘贴，可一次多张，每张 PNG/JPEG/WebP 不超过 10 MiB，同一张不能重复列出）：首条随 `POST /works` 的 `images` 提交，之后随 `POST /works/{id}/messages` 的 `images` 提交（可不带文字，不能与 `parameters` 同时提交；澄清回答沿用原任务的参考图）。`POST /works` 仍接受旧客户端的单张 `image`。任务按发送顺序把作品原图和本条消息的图依次交给模型，`user_intent.reference_images` 与图片一一对应并标注来源（`work_original`、`message`、`clarification_answer`）和宿主写的用途说明；回答图片记录所答 `clarifications` 序号，该条澄清也写入 `answer_images`，图片-only 回答同样能对应到问题。模型提示说明前面的图按该列表对应，只有其后的图才是候选帧；新图片在入队事务内校验存在、由本设备上传且不属于正在删除的会话（404/409），作品用到的每张图记录在 `remotion_work_assets`，任务记录送达删除后仍据此判断引用。上传后 24 小时仍无任何作品或任务引用的素材（如消息提交失败留下的）由每小时清理（运行时在第一个 Remotion 请求时建立并立即执行第一次）调用 `Store.prune_assets` 回收，正在删除的会话仍引用的图片留给删除流程；回收失败只记录日志，不影响上传或启动。输入锁定时客户端不附图，并在输入区下方说明原因与恢复时机。
- 公开聊天、任务公开状态与本机设备 ID 保存在使用者本地（版本列表与代码按需从服务端读取，本地只记作品当前版本指针）：桌面由 Tauri `remotion_sessions` 异步命令在阻塞线程池读写应用数据目录的 `data/remotion/sessions.sqlite3`（rusqlite bundled；进程共用一个首次调用时打开的连接，表结构按 `PRAGMA user_version` 建立与迁移，各操作参数为固定结构，前端发送的参数与 `client/tests/remotion-sessions-contract.json` 逐字比对、Rust 测试执行同一夹具），浏览器保存在当前站点的 IndexedDB `imv-remotion-sessions`（表结构与桌面库对应，事务以 strict 持久性落盘后才算完成、随后才确认送达，刷新或重启后仍在，设备 ID 随之保留；连接被浏览器关闭（如清除站点数据）或其他页签删除、升级本库时放弃该连接，下次读写重新打开）；两种实现共用 `localSessions.ts` 的存储接口与事件合并规则，不使用模型滑动窗口作为历史。会话、消息与任务按当前 API 服务地址（来源加路径，忽略大小写、默认端口与末尾斜杠）归属，切换服务后侧栏只列该服务的会话，删除只移除该服务下的本地记录；设备 ID 全局共用。服务端只暂存待送达的公开消息与事件：客户端按事件 ID 先写入本地再以 `POST /works/{id}/ack` 确认，服务端删除已送达事件；作品没有待送达事件后，已结束任务的进度、轮次与消息随之删除，只保留最新任务供重试与回答澄清。SSE 从本地游标续传，重新连接时补发一次本地游标确认；未打开、任务仍在排队或运行的本地会话由 `backgroundSync.ts` 在字效工作区挂载时与每 30 秒经 `GET /works/{id}/events?after=`（携带设备头，按编号升序分页，取空为止）拉取并按同一合并规则写入与确认，跳过 SSE 正在订阅的会话（同一会话的本地读写串行），404/410 同样标为已删除；本地库读写失败（Tauri 返回的字符串错误与 IndexedDB 错误包装为 `LocalStoreError`）不当作断线重连，订阅停止并显示原因与「刷新任务」。服务端不再提供会话快照与历史分页；侧栏与消息分页读取本地库。另以 `localStorage` 保存上次选择的会话 ID 与桌面栏宽偏好；记住的会话不在本地库（如浏览器站点数据被清除）时静默清除选择，不提示删除。
- 聊天任务等待与播放器加载分别显示，只有播放器实际加载才显示预览渲染遮罩；原有操作互斥规则保留。纯提问、问候或保持现状经独立审查后以 `answered` 终态结束，回答持久化并通过 SSE 展示，不生成候选、不发布新版本或重载播放器；首次会话和已有模板都支持问答，回答后可继续制作。
- 任务消息下显示可折叠处理时间线：宿主实际进入阶段才记录，阶段名称为白名单，不从模型普通文本推断，不提供虚构百分比或未来步骤。运行中默认展开，成功/回答后收起，失败或停止保留最后阶段；计时器在终态与卸载时清理。公开进度保存在 MySQL `remotion_job_progress`，与 `job.updated` 在同一事务发布，送达后随任务清理；同一通道通过 `job.round` 增量发布、在 `job_rounds` 逐条保存循环记录，发布层级、轮次、该轮实际执行的工具名和结论（失败时带白名单错误码与宿主固定说明）以及供审计的有界文本：每次调用模型给出的原始参数 `arguments`（4000 字）与工具的真实错误 `detail`（2000 字）、未知工具的 `requested_tool`；没有调用工具的轮次带模型回复 `message`（4000 字）或模型请求失败原因 `error_detail`（2000 字）；超长以 … 截断（截断后的参数不再是合法 JSON，前端按原文显示），完整内容仍只在私有审计。这些文本有意公开，供在聊天里审计模型实际发送的内容：参数可含计划步骤目标与候选源码，工具错误说明可含服务端路径或编译输出；工具成功结果与宿主指示不发布，工具名、错误码与固定说明仍由宿主白名单决定，终态任务不再接受记录。前端每个调用行只显示工具名与参数摘要，点开看原始 tool call；运行中默认展开最新一轮，没有调用的轮次显示模型回复或失败原因。本地会话快照 `jobs` 携带当前消息页对应的任务链路，支持历史分页、刷新和 SSE 重连，没有记录的任务不补造阶段。
- 公开循环快照携带完整轮次，普通 `job.updated` 与侧栏不重复携带累计记录；客户端合并 `job.round` 并去重，状态更新保留已收到记录。未知工具名统一为 `unknown`，模型协议失败与普通消息轮次明确区分。旧版后端 SQLite 中的会话、版本与文件不迁移、不再读取。
- 字效工作区预览在关键词为空时以当前文字的同样位置为示例关键词展示并说明（文字未改时与该挂载相同），参数与保存不受影响。
