# Remotion 客户端

新生成使用三层 ReAct 执行 `preset.create → sprite.compose → sprite.create`，最终交付为保存后的组合 Sprite。
本链路主画布固定为 1080×1920、30 FPS，界面只显示说明，不提供画布尺寸、帧率或 Sprite 类型选项。
新会话在输入框下方提供「预览时长」（只决定生成与预览的长度，字效的最终时长由合成时总线传入的渲染时长决定）：常用 3/5/8/10/15 秒或自定义（四舍五入到整帧后须为 1 帧～30 秒，与服务端契约一致，输入框不设原生 min/max，空输入时说明范围，范围外或无法解析时提示错误并禁止发送，按钮与 Enter 一致），默认 5 秒，首次请求携带所选帧数，创建后固定；首个成功版本恰好是所选时长（服务端拒绝其他时长的组合），之后的修改以已验收版本为基础、总时长由实例编排决定，成功后及恢复历史时显示实际配置。
需要其他规格时新增会话；这不代表生成的代码已通过其他尺寸、帧率或时长的适配验收。
成功版本 `spec.schema_version=2` 保存组合 Sprite。代码只是确定的样例：参数面板按 Schema 生成类型化控件
（`components/ParameterControl.tsx`：颜色、带范围的滑条、枚举下拉、开关、限长文字与关键词），分为「模板参数」
（Agent 绑定的顶层参数，云端模板里每次摆放都能修改）与「实例 · id」（各实例的内部参数），无法逐项编辑的实例回退为 JSON 文本域。
超出范围、长度或项数的输入与非法 JSON 不进入预览并阻止保存；保存只提交净变化，服务端只做 Schema 校验并立即生成新版本，不再排队渲染。
嵌套对象递归合并，数组、标量和 null 整体替换。撤销恢复成功参数，历史预览保持只读。

模型只通过服务端调用，聊天仍使用 `/api/templates` API 和作品级 SSE。
新结果交付 Export.tsx 与隔离 Player；代码、参数与时长由服务端封存，参数修订复用原播放器包，预览页注入该版本的默认值。
背景视频只留在客户端，不进入 Agent 请求或导出源码。

旧版本继续显示原画布与扁平控件。成功版本卡片提供「保存到资产」：分类下拉默认取 Agent 判断的分类（字效、滤镜、视频特效、转场），可以改选，再调用 `POST /api/sprites/publish`；
字效固定发布 `text` 字段，版本声明了关键词参数时同时发布 `keywords`。服务端先渲染参数边界样本（请求最长等待 180 秒），所选分类缺少必备参数或版本早于分类时显示服务端原因；
相同版本重复保存返回原资产。资产代码固定，参数在模板里按每次摆放修改：在云端模板编辑左侧「Remotion 资产」按分类（字效、滤镜、转场与视频特效）点「添加」，
即在预览下方时间轴新增一行，长度为资产自身时长，只能拖动起点；右侧列出名称与时间，点选后在「Remotion 资产设置」调整发布的可编辑参数、
位置与变换（滤镜与转场只有强度）和开始时间，可逐项恢复默认或移除；选中的可移动资产也能在预览画面上拖动或用方向键移动。本地模板不支持。
摆放是云端模板里的 `remotion` 轨道，随「保存模板」一次请求原子保存；保存时资产必须已发布，否则提示原因并保留修改；同一资产可以重复添加。模板预览使用阿里云 SDK，Remotion 资产画面由叠在上面的透明隔离播放器按 SDK 播放时间逐帧显示（保存到资产时会为旧版本重建预览播放器；重建失败的资产无法叠加预览），
本期客户端不包含合成渲染；整个模板的叠加视频由服务端 `POST /api/v1/overlay-renders` 提供给总线。
会话切换、新增、历史预览继续使用保存/放弃/取消保护，取消请求由服务端持久化后停止工作。

任务消息下方另有一块可折叠的「循环记录」：按轮列出宿主实际执行的工具与结论
（工具名、成功或失败，失败时带白名单错误码与宿主固定说明），逐轮点开可看该轮内容。
记录来自服务端白名单字段，不含工具参数、返回载荷、计划步骤目标或任何模型原文；
运行中默认展开，任务结束后收起，没有记录的旧任务不渲染该区域。
会话快照携带完整轮次，`job.round` 事件逐条追加并去重；`job.updated` 不重复发送轮次，
客户端在状态更新时保留已收到的记录。无效模型协议轮次明确显示失败原因。

服务端以 503 拒绝请求时，若 `detail` 是文本则原样显示（例如非 Linux 服务端缺少隔离校验环境），否则显示通用的“服务尚未就绪”；创建、消息与重试在入队前被 503 拒绝时任务并不存在，因此不再追加“检查历史会话”的提示。

展开版本卡片的代码时同时读取 `GET /versions/{id}/diagnostics`：代码按行着色并标注
error/warning 行，诊断清单点击可跳到对应行。高亮是 `codeHighlight.ts` 的展示用近似分词，
只影响颜色，不参与验收；真实结论只用服务端隔离类型检查返回的诊断。诊断读取失败时
代码仍可查看，并提供显式「重试诊断」；未保存参数等禁用状态下不发起诊断请求。

在 `client/` 执行 `bun install --frozen-lockfile`、`bun run test` 和 `bun run build`。
`remotion-composition.test.tsx` 覆盖固定画布、上传互斥、会话隔离与成功版本配置恢复，`remotion-parameters.test.tsx` 覆盖 v2 类型化控件与 JSON 回退、非法输入拦截与净变化提交；目录、删除、进度、历史与版本用例覆盖隔离预览协议和历史只读。
这些 UI 测试不执行真实模型、Remotion 或浏览器。Linux 行为验证命令见
[服务端说明](../../../../../server/src/server/remotion_templates/README.md)。
