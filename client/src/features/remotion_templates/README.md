# Remotion 字效工作区

启动默认打开主页的模板选择页面；通过“Remotion 字效”标签打开字效工作区，“模板库”标签提供 SDK 模板编辑器。
最左侧是聊天历史，列表顶部提供“新增聊天”；中间聊天，右侧上方预览、下方参数。
成功代码放在对应聊天结果下方的版本卡片中，默认折叠；不再显示顶部代码浮板。
桌面两条分隔线支持拖拽及键盘方向键调宽，记住本机栏宽；“恢复布局”还原默认比例。
桌面默认窗口为 1280×800；窄屏通过“聊天历史”抽屉选择会话，通过“聊天 / 预览与参数”切换面板。
两个工作区切换时只隐藏面板，保留模板库未保存草稿，以及字效草稿、播放器和 SSE 连接。
模板库与字效工作区首次打开才加载，切换主页保留已打开的工作区，离开整个页面时统一卸载清理。

一个作品对应一个历史会话，多次生成、澄清和修改保留在同一会话中。列表按最近活动排序，
显示标题、状态和更新时间；聊天显示服务端任务起点与耗时，刷新或切换后仍可恢复。
新增打开空白会话；切换历史、新增、断线或关闭页面均不取消后台任务，显式“停止”或确认删除会话才会取消。
旧会话中根据持久记录恢复的消息标记为“历史恢复”，不展示内部工具消息或失败候选。

任务消息下的处理卡片展示实际阶段和耗时，例如“理解你的需求 → 确认制作目标 → 生成模板代码 →
渲染并检查效果 → 调整文字布局 → 再次验收 → 准备可用结果”。阶段按实际发生顺序追加，
不显示虚构百分比或尚未开始的步骤。运行时默认展开；完成/回答后收起，可再次展开查看，
失败或停止保留最后阶段。摘要统计公开调整阶段的次数，不暴露内部候选或模型评审原文。
纯问答只展示理解和回答阶段；旧任务没有阶段记录时继续显示状态与耗时。

## 使用

1. 在 `server/` 配置并启动服务。生成器的依赖、字体和模型配置见
   [服务说明](../../../../server/src/server/remotion_templates/README.md)。
2. `client/.env` 中的 `VITE_API_URL` 指定服务地址，留空默认 `http://localhost:20070`。
   修改后重启 Vite；构建产物需要重新构建。客户端不保存模型密钥。
3. 在 `client/` 执行 `bun install --frozen-lockfile`，随后 `bun run dev` 或 `bun run tauri dev`。
4. 新会话先选择生成配置：竖屏 9:16、横屏 16:9、方形 1:1 或自定义画布；默认 1080×1920、30 FPS、5 秒。
   时长支持秒数输入及 3/5/8 秒快捷项，高级设置提供宽高和 24/25/30/60 FPS。
   宽高必须为 64～3840 的偶数，总像素不超过 8,294,400；时长不超过 30 秒，按所选帧率四舍五入到整帧且至少一帧，界面显示实际时长。
   配置随首次请求提交，图片上传和生成期间锁定；输入为空或超限时保留草稿并禁止发送。
   创建后配置固定，需要不同规格时新增会话；成功后及恢复历史时显示成功版本的实际配置。
   这不代表生成的代码已经通过其他尺寸、帧率或时长的适配验收。
   输入描述或上传 PNG/JPEG/WebP 参考图片，至少一种；图片最多 10 MiB，首轮可同时提供文字。
   服务端也会按真实图片内容校验。可直接提问，后续对话也可修改成功模板或回答追问。
   纯问答结束显示“已回答”，答案保留在历史中，不替换代码、参数或播放器。
5. 可粘贴 HTTP(S) 视频直链作为背景。链接只发给隔离播放器，不参与模型分析，不写入导出的字效代码。
   背景静音、循环并与字效共用 Remotion 时间线；源视频需要能被当前浏览器或 WebView 解码和访问。
6. 参数的合法输入立即更新本地预览，可连续调整文字、字号、颜色和位置，不自动提交服务端。
   点击“保存配置”一次提交所有净变化，检查参数合法性和服务端渲染可用性，不调用 Actor/Judge；“撤销修改”恢复上次保存值。
   保存后的用户修订作为下次对话的基线，服务端将合并后的手动修改传给模型。
   未保存时禁止发送、图片变更及复制代码，仍可连续调整参数；本地参数预览不遮挡画面或锁控件。
   生成、保存检查、预览首帧和背景加载期间，禁止发送、图片变更及参数修改；允许编辑聊天文字草稿。
   完成或失败后释放相应锁；正常播放不锁定操作。
   聊天等待在聊天区显示“正在处理”，保留当前成功预览；只有播放器实际加载时覆盖“正在渲染预览”。
7. 每个成功版本都有独立卡片，展示版本号、生成时间与来源（智能体生成 / 参数调整）。
   点击卡片预览对应版本，展开查看或复制该版本的 `Export.tsx`；失败候选和纯问答不生成版本卡片。
   历史版本只读，返回最新版本后继续调参和对话。切换仅影响本地预览，不回滚服务端，也不改变后续修改的基线。
   正在查看旧版本时，新成功结果仍加入聊天，保留用户选中的预览。
   未保存参数不能复制为成功代码。保存失败保留上个成功版本和参数草稿，可继续调整、再次保存或撤销，
   事件连接断开时自动续传，快照读取失败可“刷新任务”，终止的任务可明确重试，不自动重发写请求。
   新版本或 Export 读取失败单独提示，保留旧代码与参数草稿，继续消费后续事件；“重新读取结果”只读取当前快照和产物，不重新生成。
   未保存草稿、提交中或读取中禁止普通恢复操作；本次保存响应未知或结果读取失败时允许只读恢复，不自动重复提交。
   保存请求绑定当前成功版本，只发送与其默认参数不同的值。
8. 卡片上的“复制代码”复制带该版本成功默认参数的 `Export.tsx`，可在自己的 Remotion 项目中使用；
   消费方仍需安装 React/Remotion 并加载 Noto Sans CJK SC 400/700。导出文件包含画布尺寸和时长常量。
   历史列表顶部的“新增聊天”清空当前视图的聊天、图片、代码、参数和背景，恢复默认生成配置；下一次发送才创建新作品，旧会话仍在历史中。
   新增、切换历史会话或预览旧版本遇到未保存参数时，可选择保存并切换、放弃修改并切换或取消；保存失败仍留在当前会话，取得成功版本后才切换。

## 删除聊天

历史列表和窄屏抽屉的每条会话都有删除按钮，确认后调用 `DELETE /works/{id}`。
删除会清理全部聊天、历史代码和对应数据目录；运行任务先停止，未保存参数直接放弃。
删除当前会话后进入空白视图并释放播放器、SSE 和本地选中记录；删除其他会话不影响当前草稿。
删除失败或响应未知时不会自动重发，弹窗提供“重试删除”；当前目标会话禁止继续编辑。
服务端清理未完成的条目显示“等待清理”，仍可从删除按钮重试。
其他窗口删除当前会话时，通过 SSE 终止信号或恢复请求的 404/410 清空视图，停止重连。

## 历史与事件协议

提交仍为 POST；客户端不轮询 `/jobs/{id}`。先读取 `/works/{id}/session` 的消息、当前任务、
成功版本指针与事件游标，再订阅 `/works/{id}/stream?after=游标`。连接按作品维持，支持后续修改任务。
成功版本目录来自 `/works/{id}/versions`；通过任务的 `result_version_id` 放回对应聊天消息，
旧任务缺少关联信息时在消息末尾保留版本入口。历史导出按需读取，失败可单独重试。
公开事件为 `message.created`、`job.updated`、`version.ready`，每条都带稳定编号；
收到成功指针后再读取版本及导出，不推送尚未验收的代码片段。
`job.updated` 的 `progress` 携带完整公开阶段区间；快照的 `jobs` 提供当前消息页各任务的链路。
更早分页只补充历史任务，不覆盖 SSE 已推进的当前任务；刷新、会话切换和重连均从持久记录恢复。
阶段名称来自固定枚举，客户端不把模型普通回答解释成处理事件。

断线后等待 2 秒，从最后已应用的 ID 续传；请求同时发送 `Last-Event-ID`。
15 秒空闲心跳由服务端发送，45 秒无字节则中止连接并重连；409 游标失效时重取快照。
主应用对既有 localhost 和 Tauri 来源允许该请求头；反向代理需关闭 SSE 缓冲，并允许超过心跳间隔的连接空闲时间。

浏览器 localStorage 保存当前服务最后选中的会话 ID 及桌面三栏尺寸偏好，不保存聊天和代码。刷新后以服务端历史为准，恢复最新成功版本。
图片使用服务端素材 ID 恢复；未发送文字、未保存参数和背景视频地址不入库，刷新页面不恢复这些本地草稿。
切换历史会话前保护未保存参数；确认切换后清空本地草稿。
列表支持加载更多，聊天支持加载更早消息；历史读取失败保留已有内容并提供刷新入口。
关闭连接会清理读请求、定时器和播放器，但不会删除历史或取消任务。

## 模块边界

- `api.ts`：普通请求和超时；`events.ts`：SSE 分帧、续传请求与心跳超时；`model.ts`：公开契约与参数边界。
- `useTemplateSession.ts`：快照恢复、当前会话订阅、用户操作、消息分页、最新编辑基线与独立历史预览。
- `useWorkHistory.ts` / `HistorySidebar`：历史分页、刷新及窄屏抽屉；`TaskStatus`：基于服务端区间显示可折叠时间线与耗时，终态和卸载清理计时器。
- `ChatPanel` / `VersionCard`：聊天输入、任务关联的成功版本卡片、独立代码读取与复制。
- `useTemplateVersions.ts`：成功版本目录恢复、合并最新结果与独立重试。
- `WorkspacePanels`：可拖拽三栏、尺寸偏好与窄屏切换，复用 shadcn/ui 分栏控件。
- `CompositionSettings` / `composition.ts`：生成前配置表单、输入边界及秒到整帧转换；会话 hook 在提交和上传期间再次守卫。
- `ParametersPanel`：根据已验收 JSON Schema 的 `x-imv-target` 生成标量控件，提供本地草稿、显式保存与撤销。
- `PreviewPanel`：sandbox iframe 与带通道、请求编号的消息握手，不在客户端编译或执行 TSX。
- `RemotionWorkspace`：统一操作锁、服务提示及响应式布局。

Player 和 TSX 由服务端在隔离渲染器内打成一份受证据清单保护的包。iframe 不允许同源权限，
只允许脚本、受管字体和背景媒体；父页面检查消息来源、当前通道与请求编号。
首帧确认或错误释放加载锁，20 秒未确认显示超时并允许重试。
旧版本如果没有交互包或带默认值的导出，需要重新生成，不在浏览器中降级执行旧源码。

## 验证

在 `client/` 执行：

```sh
bun install --frozen-lockfile
bun run test
bun run build
```

`tests/remotion.test.tsx` 使用 Bun、Happy DOM 与 React Testing Library，隔离 HTTP、剪贴板和 iframe 导航。
`remotion-session.test.tsx` 覆盖核心互斥；`remotion-history.test.tsx` 覆盖历史选择、刷新、图片、分页、
断线续传、去重及迟到版本隔离；`remotion-events.test.ts` 覆盖 UTF-8 分块、CRLF、多行 data、游标失效、
坏帧和心跳超时。原有生成、澄清、复制、预览锁及模板库用例同时保留。
参数用例覆盖连续预览不自动提交、净变化批量保存、重复保存互斥、失败保留草稿、撤销、只读恢复、
新增/历史切换的保存与放弃及取消、旧预览回执隔离、卸载清理和 StrictMode 历史恢复。
问答回归覆盖请求未返回时不显示渲染遮罩、原播放器不重载、SSE 回答后解锁及刷新恢复历史。
`remotion-progress.test.tsx` 覆盖阶段计时、折叠、失败/停止保留、问答短链路、旧任务兼容、
SSE 推进与去重、断线和刷新恢复、历史分页并发、每个任务一张卡片及会话切换隔离。
`remotion-composition.test.tsx` 覆盖配置默认值、预设和自定义画布、小数时长取整、帧率、空值与边界、
首次文字/图片请求载荷、上传失败恢复、配置锁、新增重置及历史成功配置恢复；后续消息不覆盖生成配置。

`remotion-versions.test.tsx` 覆盖成功卡片折叠、独立导出、目录/代码失败重试、剪贴板失败、
历史只读、返回最新基线、保存/放弃/取消导航、SSE 更新时保留历史选择、迟到读取与卸载清理。

浏览器布局回归（需本机安装 Chrome；使用 `playwright-core`，不自动下载浏览器）：

```sh
# 终端一
bun run dev --host 127.0.0.1 --port 1421
# 终端二
bun run test:remotion-browser
```

可通过 `IMV_BROWSER_URL` 指向其他本地前端端口，`IMV_CHROME_PATH` 指定 Chrome 可执行文件。
脚本拦截业务 API，模拟 iframe 消息协议；检查两条分隔线的拖拽、键盘、最小宽度、刷新恢复、
重置和坏存储回退，以及 1440/1280/390 像素布局、版本切换、未保存保护和抽屉新增。
截图输出到命令打印的临时目录，浏览器始终在结束时关闭。该脚本不运行模型、不验证真实视频播放。
SDK 的 CSS 放在 `sdk` 层，位于基础样式之后、应用工具类之前，防止覆盖按钮等业务控件的样式。

真实播放需另行检查：生成模板，加载可访问 MP4，播放并拖动时间轴，修改文字/字号/颜色/位置，
检查本地调整可连续预览，保存检查期间锁定和结束后恢复，再复制到 Remotion 项目中确认默认参数。
另外检查窄屏面板切换、新增清空以及无法加载的视频；模拟 DOM 测试不证明媒体解码或 Tauri 跨平台可用。

本机 KDE/Wayland 若启动报 `Error 71 (Protocol error)` 或 GBM buffer 错误，可使用用户确认有效的启动方式：

```sh
env WEBKIT_DISABLE_DMABUF_RENDERER=1 bun run tauri dev
```

该变量仅影响此次 WebKit 启动，不写入业务代码或全局环境；仍需安装本机 WebKit/GStreamer 所需的媒体插件。
本机若提示 `autoaudiosink` 或 `scaletempo` 缺失，检查 `gst-plugins-good`；缺少插件可能导致 WebKit 进程退出，
不能把桌面窗口成功打开等同于播放器可用。

`remotion-deletion.test.tsx` 覆盖删除确认/取消、失败重试、防重复写入、当前与其他会话草稿、迟到响应和远端删除。浏览器脚本还验证桌面删除确认与窄屏抽屉删除后的播放器清理。
