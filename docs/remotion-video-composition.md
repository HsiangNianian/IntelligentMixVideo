# Remotion 接入 video_composition

当前交付分支已合并 `upstream/dev@38f099a`（v0.9.0）。上游单 Sprite 的 `/api/sprites/render`、短文字定格及长视频分块拼接均保留；`video_composition` 仍调用共享内部渲染函数，并使用本文的合成时钟适配。文末早期的未提交状态、测试结果及临时备份路径属于当时的排查记录，当前交付以最后一条验证记录和 PR 为准。

调用方仍使用 `POST /api/v1/video-compositions`，只传既有 `styleId`、业务文案、标题、音频或素材等字段。最新上游的 Sprite 发布记录保存于 MySQL，摆放保存在模板 `tracks[target=remotion]`，新字效通过 `text_target` 绑定文字对象，转场通过 `transition_boundary` 绑定交界处；参数覆盖保存在 `editor.remotion`，不再调用独立绑定 API。无需传 Remotion 源码、参数或单独调用 overlay-renders。

## 配置与数据流

1. 在字效工作区生成并保存资产；生成、校验、发布流程保持 upstream/dev 原样。合成侧读取已发布契约，示例文字只用于生成和编辑预览。
2. 在云端模板添加 Remotion 资产，字效在右侧选择标题或底部字幕（`text_target`），转场选择交界处（`transition_boundary`），滤镜及视频特效按分类识别。新模板不再增加独立用途下拉；旧 `editor.remotion.businessTarget` 字段保留读写与私有快照兼容，新槽位字段优先。
3. 标题使用请求 `title` 和 segmentation 的 `title_keyword`。新字效绑定采用对应标题对象的实际显示区间，旧用途快照沿用自身摆放区间，均裁到成片以内；IMS 标题继续遵循模板区间，包括无声模式。
4. 字幕使用 segmentation 二次切分后的正文、起止时间和继承关键词；兼容历史 `subtitle_parts`。清理标点的规则与 IMS 共用，保留中英文问号。仅使用当前切片继承的关键词，空词或不匹配时清空高亮。新发布按上游契约接收关键词字符串列表，组件负责文字内高亮；历史码点区间契约仍只传首次命中区间。多行字效（声明 `lineStartFrames`，固定 N 行）把同一句 ASR 句子（切片 `group_id` 句内序号为 1 时开始新句）里最多 N 个连续字幕合成一个实例：正文用换行连接，`lineStartFrames` 是各行切片开始的帧（从实例起点算起；固定时钟资产换算到预览时钟），第 i 行在第 i 个切片开始时出现，整组在最后一个切片结束时清空；换句时即使没有填满也开始新组，再加一行会超过资产文字上限或行起点上限（3600 帧）时同样提前分组，关键词注入各行命中的词，排版预检只测量最后一行出现之后的帧。标题绑定多行字效时按标题里的换行分行（空行忽略，多出的并入最后一行，各行同时出现）；没有换行时整段标题放在第一行，其余行不显示。单行字效仍逐个切片显示。
5. 有声任务以 ASR 返回的完整音频时长为总长，保留首尾静音；无声任务以 `processRules.videoDuration` 为总长且不生成字幕。无正文有声模式若有标题，单独执行一次仅标题提词。
6. 所有实例按绑定顺序叠放，使用共享渲染名额、隔离 Chrome 和 FFmpeg 输出无音频 VP9 Alpha WebM。资产画布按 Cover 缩放至合成画布。渲染前在同一名额内做排版预检（见 `remotion_templates/README.md` 的 Text fit）：带 `text`、`fontSize` 参数的字效按实际标题、字幕和实际运行的源码测量，被裁切、超出成片里看得到的画布部分或只显示一部分时把 `fontSize` 缩到放得下的最大值；英文标题和字幕的单行字效另要求单行，译文过长时缩到仍能单行显示的最大字号，避免换行压到另一语言的文字，缩到最小字号仍换行时保留整段放得下的字号（尽力单行，不因此失败）；启用英文字幕时，字幕轨的单行字效换行后朝远离另一语言的方向展开——英文字幕向下（第一行留在原单行的位置）、中文字幕向上（最后一行留在原单行的位置），两条字幕因此不会互相压住；没有启用英文字幕时中文字幕保持原本的居中展开；这次渲染的摆放只按多出行高的一半移动，且不移出成片可见的画布部分（不改保存的摆放）；缩到发布的最小字号后若只因摆放位置仍出画布，则在这次渲染里把摆放按最短距离平移回画布内（不改保存的摆放）；仍放不下时以 `remotion_text_too_long` 失败，不输出被裁切的文字。没有这两个参数的旧资产不参与。透明视频上传 `imv/video_composition/{task_id}/overlay.webm`，核对公共读取后直接加入 IMS 最后一条视频轨，从 0 秒对齐。

本次同步保留 #113 的槽位行为：设置 `text_target` 后对应 IMS 文字由 Remotion 替代；旧的独立用途快照仍可两套并存。**实际仍输出的 IMS 文字在 Remotion 视频之上**；不增加 FFmpeg 后置编码。底片滤镜继续交给 IMS；Remotion 只提供字效及透明装饰。编辑器目前以透明 iframe 叠在 SDK 画面上，重叠区域的前后关系以真实成片为准，界面已提示；该预览不是云端 IMS 合成结果。

保存接口也接受没有 `text_target`、但保留 `editor.remotion.businessTarget=title/subtitle` 的旧字效轨道；替换发布资产时不必迁移槽位，继续保留 IMS 与 Remotion 共存。字效分类、已发布资产、画布、参数范围与禁止正文/关键词覆盖的校验仍然执行；滤镜、视频特效或转场携带标题/字幕用途时保存返回 422，避免模板保存成功而每次合成都失败。客户端读取旧用途时不自动补新槽位，往返保存保留共存；右侧说明当前显示方式，只有用户重新选择作用对象才切换到新槽位语义。

## 动态资产契约与旧资产

上游发布的字效直接使用 `text_prop`、可选 `keywords_prop` 和参数 Schema 注入正文/关键词，不要求资产携带额外的 `x-imv-*` 标记，无需重新生成或发布。同一任务只读封存资产，并在内存副本上覆盖业务文字与运营样式。

- **上游固定时长资产**：合成侧 `remotion_timing.py` / `remotion-timing.mjs` 只解析并打包已封存模块与可信时间宿主，不执行生成代码，不写回资产。宿主把实际区间第 0～N−1 帧映射到资产第 0～M−1 帧，取最近的整数帧（与 Remotion 自身一致，按帧下标取值的资产不会得到小数帧）；其内部 Sequence、`useCurrentFrame`、`useVideoConfig` 和原始 FPS 使用同一个发布时钟。整套入场、停留和出场随业务区间同比变速，超过原始时长也不会在内部固定 Sequence 末尾提前消失。外层仍严格使用字幕起止时间，间隙保持透明；不从源码猜入场/出场边界，也不改写动画表达式。
- **1～2 帧极短字幕**：冻结到发布的 `static_frame`（非零时）；上游未提供则使用原动画中间帧，避免两帧全落在透明端点。中间帧不保证任意资产都可读，稀疏或非文字可见区间仍需真实资产验证；不延长字幕或自动修订资产。
- **已声明动态时长的历史资产**：继续识别 `x-imv-dynamic-duration: true` 或 `x-imv-role: duration` 的整数参数，按原路径传入实际帧数，不重复拉伸其动画。显式为 false 的资产使用固定时钟。非法声明仍报错。
- 正文为字符串；新发布关键词为字符串列表，例如 `["今天"]`。已封存的旧字符串/码点区间契约仍兼容，区间按 Unicode **码点**半开区间注入，例如 `😀今天` 的「今天」是 `[[1,3]]`。空词或未命中清空例词；未声明关键词能力的资产不强加高亮。
- 原始源码 SHA-256 在适配前验证；同一资产只打包一次供所有字幕和标题复用。文字、颜色、字体和宿主变换保持既有参数路径。打包只允许上游现有 React/Remotion 导入，执行仍使用原 overlay-worker 的 Linux 隔离环境。
- 不新增参数猜测或文字截断。缺少正文映射、损坏的资产时长、参数越界等仍明确失败；硬编码文案必须先成为可替换参数。文字绑定必须声明文字对象或保留有效的旧用途，不能作为装饰输出示例；非文字资产按发布分类识别。
- 该时钟宿主只由 `video_composition` 使用，依赖仓库已锁定 Remotion 的上下文接口；升级渲染依赖时需运行真实时钟回归。独立 `/api/v1/overlay-renders`、生成、发布及所有编辑预览保持上游行为。

编辑预览沿用 upstream/dev 的对象槽位规则：文字内容与区间跟随所绑定对象，转场围绕指定交界处显示，保留参数覆盖和宿主变换。不恢复此前额外的 `/api/sprites/preview-input`、动态绘制等待或播放器包升级。字幕业务正文与时间仍在实际合成时取 segmentation。

## 失败、恢复与配置

`IMV_OVERLAY_MAX_SECONDS` 默认 300 秒（5 分钟），是限制而非默认片长，可由环境变量覆盖；有实际字效的超限任务失败，不截断音频。`IMV_OVERLAY_RENDER_TIMEOUT_SECONDS` 默认 1800 秒（30 分钟）；共享渲染名额为 3，`COMPOSITION_CONCURRENCY` 默认也为 3。单个任务仍用一个绘制标签页，排队、成片校验与上传不计入渲染超时；复用既有浏览器、字体、bwrap、Node、FFmpeg 和 ZOS 配置，不新增秘密字段。没有可显示正文时跳过对应绑定，没有实际实例时跳过 Remotion 渲染。

首次准备阶段从同一份 IMS 模板提取 Remotion 轨道，再把模板更新时间、发布源码及参数一起保存到私有任务快照；后续模板编辑不影响本单。快照固定后（包括恢复时）只要有会实际渲染的摆放——视觉资产、遇非空标题的标题绑定、有声且有文案的字幕绑定——就先检查隔离渲染环境（bwrap、prlimit、Node、FFprobe、浏览器与字体）；缺失时在 `template` 阶段以 `remotion_render_environment_unavailable` 失败，不调用 ASR 与切片模型。没有可显示内容的绑定不要求该环境。上传结果保存到 `remotion_result` 后恢复直接复用；中断在结果保存之前可重跑本地确定性渲染。旧任务没有 Remotion 快照时沿用原行为，不读取新绑定。渲染或上传失败整单失败，不返回缺失字效的成功成片。

日志仍只有七个模块，资产绑定摘要归 `template`，透明视频结果及最终 IMS Timeline 归 `timeline`；发布源码只进私有任务快照，不进入执行日志或 GET/回调。典型错误：`remotion_asset_not_adapted`、`remotion_duration_too_long`、`remotion_render_environment_unavailable`、`remotion_text_too_long`、`remotion_render_failed`。

计划、时长适配打包、渲染或叠加视频上传失败时，清理工作目录前将 worker 输出与完整异常链（附子进程 stderr，例如打包器缺少依赖的原因）保存到 `server/.log/video_composition/<task_id>/errors/remotion-worker.log` 与 `remotion-error.log`（私有目录权限 0700），随任务目录参与 50 MB 容量清理；旧 `composition-overlay-failures/` 保留、不迁移。不保留视频及编译产物；七模块 JSON 只保留安全诊断及 `error_log[].error.detail_log_path`（`errors/remotion-error.log`），不嵌入详细正文或通过 GET/回调公开路径。诊断写入失败不覆盖原始任务错误。成功仍清理整个临时工作目录。

## 已确认、尚待后续实现的业务要求

2026-10-13 本轮先同步上游及兼容代码，以下要求不作为已经完成的功能：

- `video_composition` 只负责业务数据与最终 Timeline；短字幕完整显示和取消入出场交由 Remotion 渲染侧处理，不在合成侧新增阈值。
- 合成通过 Remotion 渲染接口传入最终字幕、总时长、模板及素材切点，取得整段透明视频链接；当前仍是内部函数调用，HTTP 接口尚不接收 segmentation。
- IMS 字幕只使用模板样式，时间完全来自 segmentation；当前上游新模板已限定字幕覆盖全片，兼容旧数据的具体处理需随接口改造验收。
- 当前最终字幕内重复出现的关键词全部强调，跨二次切片的关键词继承规则不变；当前 IMS 与旧区间契约仍仅强调首次。
- 闪白跟随素材和数字人的切换，IMS 与 Remotion 转场都显示，闪白不盖字幕；当前上游每个交界处只允许一个转场，尚未实现这一共存规则。
- 此前确认的 IMS 与 Remotion 文字共存，与 #113 的新文字槽位替代规则仍有差异，后续接入应明确落实；滤镜作用范围等待真实成片验证。
