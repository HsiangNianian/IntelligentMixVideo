# Remotion 字效服务协作约定

适用于 `server/src/server/remotion_templates/`，补充根目录与 `server/` 的 `AGENTS.md`；使用说明见本目录 README。

渲染资源与 worker 见 `server/src/server/remotion/AGENTS.md`；客户端：字效工作区见 `client/src/features/remotion_templates/AGENTS.md`，模板中的 Remotion 片段与叠加预览见 `client/src/features/templates/AGENTS.md`，字体库页面见 `client/src/features/fonts/AGENTS.md`。

- Remotion 文字模板生成服务位于 `server/src/server/remotion_templates/`，Python 包名为 `server.remotion_templates`，挂载 `/api/templates`；作品、任务、版本、模型窗口、待送达事件与叠加渲染任务保存在共享 MySQL（`tables.py`，首次使用建表），后端不再创建 SQLite 或运行锁、只按单实例部署：库里的租约行 `remotion_instance` 强制这一点（启动获取、每 10 秒续期、正常退出释放，崩溃的实例 30 秒后过期；未过期时第二个实例的首个 Remotion 请求返回 503，失去租约的实例不再领取任务），要求 MySQL 8.0 及以上；封存版本文件、参考图与资产预览包是 `imv/remotion/` 下的对象（`object_store.py`：`ZOS_BUCKET` 非空时以 public-read 存 ZOS，版本的内部文件 `candidate.json`/`spec.json`/`tool-validation.json` 知道版本 ID 即可读取，为空时存 `IMV_DATA_DIR/objects`；填了桶但其余配置不全即报错），后端经 SHA-256 校验的本地缓存读取；模块 `.data/` 只放任务草稿、缓存与私有审计 `audit/<work_id>/<job_id>.jsonl`（删除会话时整个目录一并删除）。每个作品属于创建它的客户端设备：作品相关 JSON 接口必须携带 `X-IMV-Device`，其他设备的作品视为不存在（删除为 204 空操作）；打开的作品经 SSE 接收事件（空闲时休眠到本作品有事务提交才读取库，5 秒读取一次兜底），其他作品经 `GET /works/{id}/events?after=` 分页补取，写入本地后同样确认，服务端不提供作品列表；预览页、字体、参考图与产物下载按不可猜测的 ID 访问、不校验设备。每小时清理一次：未确认送达的事件 `IMV_UNDELIVERED_EVENT_DAYS`（7 天）、私有审计 `IMV_AUDIT_RETENTION_DAYS`（14 天）、设备 `IMV_DEVICE_RETENTION_DAYS`（90 天）未活跃则删除其会话数据，并重试清理未完成的删除，删除 30 天前结束且无待发回调的叠加渲染任务与 30 天未用的读取缓存（各步骤与各作品互不影响），已发布 Sprite 不受影响。使用说明维护在模块内 README。
- 创建作品、更早（PR74）版本或播放器包早于默认值注入的组合版本的参数补丁消息与此类参数任务的重试在入队前检查隔离校验环境（非 Linux 或缺少 `bwrap`/`prlimit`/`taskset`/`node`），不满足返回 503（提问、澄清回复、文字修改与普通重试不预检，模型可能无需校验器即可回答） 并说明原因，不留下作品或任务，客户端显示该 503 的文本 `detail` 且不再提示检查历史会话；仅 macOS 开发可设 `IMV_ALLOW_UNSANDBOXED_WORKER=true`，以普通 Node 运行 `tool-validation-worker.mjs`、`presentation-worker.mjs` 与 `worker.mjs`（只要求 `node`，生成代码无隔离，启动时记警告；默认关闭，其他系统一律忽略；`overlay-worker.mjs` 不在名单内，叠加渲染含重启恢复始终需要 Linux 沙箱）；运行中校验器无法启动时 `preset.create`/`sprite.create` 返回 `VALIDATION_UNAVAILABLE`（原始异常留在私有审计，不再变成 `PRESET_STORE_FAILED`/`SPRITE_STORE_FAILED`；`preset.modify` 只校验契约，不启动校验器），存储错误码仅用于存储失败。
- 成功版本只读诊断接口复用 `validate.code` 的契约检查与隔离 TypeScript 语言服务，不新增诊断持久化表；先按证据清单校验封存产物（改写返回 404），隔离运行时不可用返回 503，不把「未检查」表示为「无诊断」；只读接口不排队、不发布。
- Remotion 字效使用共享字体库：MySQL `remotion_fonts`（`font_store.py`，只增不删，ID 与家族名不变，只有显示名、预览条与字形（slot 与字重）可被修正，首次使用建表）一行是一个字体文件，同一家族的常规、粗体、斜体、粗斜体文件（可缺）组成一张字体卡片、共用一个家族名（卡片第一个文件以家族名本身、之后的文件以「家族名<TAB>字形」登记，唯一列仍为卡片保留名称），渲染时按字重与斜体选用对应文件，文件是 `imv/remotion/fonts/<id>/` 下的对象（ZOS 已配置时 public-read，否则本地对象目录，与 `object_store.py` 一致）。库里有三类：系统默认字体 `Noto Sans CJK SC`（`source=system`，随系统安装、没有文件，运行时首次使用时登记，所以库永远不空）、预装字体（16 个免费 OFL 字体，含与 IMS `Font` 同名的 `Source Han Sans CN`、`Source Han Serif CN`，其余 IMS 字体因专有或再分发条款未确认不随包，持有授权者可上传；随后端包发布在 `remotion_templates/bundled_fonts/<文件名>.xz`，`font_catalog.json` 固定每个字体解压后的体积与 SHA-256 并记录来源地址作出处；`FontStore.sync` 在 Remotion 运行时建立后后台解压、校验并复制进 ZOS 与注册表，每小时补同步，不需要联网，所以访问不了 GitHub 的生产环境也一样可用；`IMV_INSTALL_BUNDLED_FONTS=false` 不安装；字体按 OFL 再分发，`bundled_fonts/LICENSES.txt` 保留每个字体的许可证与版权声明，增删字体要同时更新目录、字体包与许可证，测试核对三者一致）与用户上传（`POST /api/templates/fonts`，multipart `file`、选填 `preview` 与 `label`，需 `X-IMV-Device`；只收 .ttf/.otf，上限 `IMV_FONT_UPLOAD_MAX_BYTES` 默认 50 MiB（超出 413，说明上限），对象存储或数据库失败 503 并写服务端日志 `Font upload failed`，后端只用有边界检查的纯 Python 读取 name 表得到家族名与显示名而不解码字体：家族名取英文（默认语言）名称，显示名优先取字体自己的中文名，不取文件名；按文件内容（SHA-256）去重，同一个文件只登记一次且上传幂等：库里已有同一个文件时返回 200 和它所在的卡片（新登记为 201，超时后重试或别人再传同一个文件都得到同一结果），与尚未装进库的预装字体相同时 422；按文件样式（name ID 17，没有则 ID 2）归入卡片：Italic/Oblique 为斜体，其余词是字重，常规与 Bold（含其斜体）在该家族用户上传的卡片里对应字形还空着时加入，与上传顺序无关；其他字重（Thin、Black 等）单独成卡片、家族名与显示名带字重（其斜体进同一张卡片）；可变字体忽略字重词；同一字形的其他版本，或与尚未装进库的预装字体、系统已装或保留名同名时，依次改用旧式家族名（name ID 1）、加版本号、加序号（可加入同名且该字形空着的上传卡片），预装与系统卡片不接受上传加入；生成的 fontconfig 为每个字体文件（预装与上传）加一条扫描规则，按沙箱内文件路径把它的家族名替换为卡片家族名，名称相同的文件因此互不混淆（预装可变字体自带的默认实例旧式名，如 `Noto Sans SC Thin`，不再指向它），同一卡片的文件由 fontconfig 按自身字重与斜体选用；Agent 字体清单每张卡片一项并列出已有字形；此前占用了某个预装字体家族名的上传使同步跳过该预装字体并记警告；字体不可删除；预览条由上传者浏览器用该字体按同一规则（`features/fonts/names.ts`）读出的显示名画出，作为 `label` 上传，文字与显示名不同的预览条不保存，只保留透明度；此前以文件名为显示名、一律按常规体登记的上传字体在下次 `FontStore.sync` 时改用字体自己的显示名与字形（家族名不变），旧预览条画的是文件名，作废后改显示文字名称）。渲染沙箱没有网络：后端把库里的字体按注册表哈希校验后缓存到 `IMV_DATA_DIR/fonts/files`，沙箱把该目录只读挂到 `/imv-fonts` 并设置 `FONTCONFIG_FILE`（`Renderer.command` 唯一构造点），各 worker 的 Chrome 按 CSS 字体名解析，不逐个 worker 改字体加载，也不新增运行证据字段；macOS 无沙箱开发模式不加载。Agent 的字体来自数据库：Executor 规则追加字体库枚举（名称、风格、字重），字效必须暴露 `fontFamily` 枚举参数（取值须都在字体库里、默认值是枚举之一，由 `categories.category_problems(fonts=...)` 在 `sprite.create` 检查；发布更早的版本不要求该参数），Agent 只收到用户参考图、看不到自己的渲染，靠描述、参考图与风格标签选择；保存时宿主把 `fontFamily` 的枚举换成普通字符串（`maxLength` 100，`open_font_schema`），因为库会随上传增长，之后的选择按实时库校验（`fonts.require_family`，模板摆放覆盖经 `placement.resolve` 保存即校验，手动参数修订经 `patch_parameters`），不受生成时冻结的枚举限制，字体选择就保存在模板轨道的 `editor.remotion.parameters` 里。预览页以 `#imv-preview-fonts` 列出有文件的字体文件（卡片家族名与字重、斜体描述；斜体文件不带旧格式的 `weight`，卡片有字形之前构建的播放器跳过它们），播放器注册为惰性 `FontFace`，经 `GET /api/templates/fonts/{id}`（本机没缓存时先从对象存储取回）读取。叠加渲染与排版预检在代码或参数点名了本机尚未缓存的库内字体时先取回，仍取不到以 `font_unavailable` 失败，不悄悄回落默认字体。已发布资产与旧版本不受影响，没有 `fontFamily` 的旧字效在模板里不显示字体选择。
- Remotion 渲染性能：`IMV_OVERLAY_FRAME_CONCURRENCY` 控制每块页数上限（默认 4，准入按有效 CPU 自动降低实际页数并传入 worker），`IMV_OVERLAY_CHUNK_CONCURRENCY` 控制单视频并行块数（默认且最多 6）。整段叠加/视频合成默认 `IMV_OVERLAY_CHUNKED=true`，与单 Sprite 共用固定 15 秒分块及无损拼接：不超过 15 秒只用一块，尾块保留剩余帧，帧区间连续完整、动画保持绝对时钟。视频名额和 `COMPOSITION_CONCURRENCY` 默认均为 6，全部视频另共用 `IMV_OVERLAY_GLOBAL_CHUNK_CONCURRENCY=36` 切片上限，资源充足时允许六视频各六块；`RenderCapacity` 按 CPU/内存余量降低实际切片并发或等待（最长 `IMV_OVERLAY_RESOURCE_WAIT_SECONDS=300`，超时返回 `resource_unavailable`，合成为 `remotion_resource_unavailable`，提示调用方稍后重新提交，不自动重试终态任务），覆盖排版、渲染与校验，取消/失败释放。`IMV_RENDER_CPU_RESERVE_PERCENT`/`IMV_RENDER_MEMORY_RESERVE_PERCENT` 默认各预留 25%，Linux 所有 worker 经 `taskset` 继承同一 CPU 核范围并考虑祖先 cgroup v2 配额（v1 只使用宿主亲和性和内存信息）；每页与每视频额外浏览器预算均为 `IMV_OVERLAY_CHUNK_MEMORY_MB=1024` MiB，全局再由 `IMV_RENDER_MAX_CPUS=144` 个逻辑 CPU 与 `IMV_RENDER_MAX_MEMORY_MB=153600` MiB 封顶（36 块×4 页，加六视频额外预算共 150 GiB），与整机/cgroup 预留后余量取更严者；编码线程也受同一核范围限制，cgroup 有余量仍不能越过宿主总内存 25% 的保护线；只作保守准入，不是内存硬上限，Python 直接部署还需 systemd MemoryHigh/MemoryMax（由部署环境配置）。VP9 `IMV_OVERLAY_VP9_CPU_USED`/`IMV_OVERLAY_VP9_THREADS` 默认分别为 4/2，可通过环境变量覆盖；只修改实际编码命令，不改共享内存输入线程或最终复制封装。4.0.534 配套 Headless Shell 须在部署阶段下载并设置 `IMV_BROWSER_EXECUTABLE`，既有系统 Chrome 不自动替换，不开放 GPU 或沙箱网络。阶段性能与资源准入诊断只写私有 JSON 和清理前的数值服务日志；并行时 `rendered_ms` 包含预编码等待，`encoded_ms` 只是最后封装，以墙钟比较性能。只有实际多块才检查 FFmpeg：已知时长在受理时检查，音频时长解析后及恢复任务在渲染前检查；分块拼接超时和取消均回收 FFmpeg。`slot_wait_ms` 与 `resource_wait_ms` 分别计时、不重叠。渲染默认值集中在 `remotion_templates/settings.py`，合成调度默认值在 `video_composition/settings.py`；`.env.example` 的新增渲染项只保留 CPU/内存预留比例，其余调优参数默认无需填写、按需仍可用环境变量覆盖。
- Remotion 配置类与加载函数位于 `remotion_templates/settings.py`，通过 `server.remotion_templates.settings` 导入；继续复用 `config_base.CommonSettings` 读取 `server/.env`，相对数据目录和默认 `server/remotion/` 渲染资源位置保持不变。视频合成与叠加渲染共用的成片时长上限 `IMV_OVERLAY_MAX_SECONDS` 默认 300 秒（5 分钟），可由环境变量覆盖。
- 总线取 Remotion 成片：`POST /api/v1/overlay-renders`（JSON camelCase：`placements`、可选 `audioUrl`、`duration`、`callbackUrl`；`placements` 为最多 100 项、先者在下的 `{spriteId, start, duration?, editor?}`，由总线从模板的 `remotion` 轨道读取，`editor` 为该轨道 editor 的原样转发，只能含 `remotion` 参数覆盖与宿主变换；总线转发之前片段按发布默认值渲染）异步受理，`GET /api/v1/overlay-renders/{taskId}` 查询。服务端按请求里的摆放读取 Remotion 库中已发布的 Sprite（不查询 IMS 模板；摆放随任务一并保存，恢复时按保存的摆放渲染），要求画布尺寸与帧率一致，按发布参数契约合并参数覆盖、校验宿主变换（不合契约受理即 422），每个 Sprite 放在共享宿主层 `host-layer.tsx` 里绕内容区域中心移动、缩放、旋转与调整不透明度，宿主层同时让组合 Sprite 的实例盒子（`data-imv-instance` 的父元素）不裁剪内容，只受画布限制（新组合的代码不再带 overflow hidden，更早封存的由宿主层与预览页的覆盖样式取消，排版预检与叠加渲染、预览一致；内容自己的固定框仍按原规则检查），在渲染前按这次摆放真正携带的文字做排版预检（模板叠加与单 Sprite 渲染都做，占用渲染名额；隔离浏览器挂载每份不同内容自己的参数值，按该 Sprite 在成片中播放的长度（它读到的 `durationInFrames`，定格切片为预览长度）挂载、被总长截断的摆放只在成片里出现的帧上采样，并按摆放的宿主变换（位置、缩放、旋转；不透明度不影响排版）判断是否出画布，长度或变换不同的摆放分别测量，一次渲染的所有字效在同一次浏览器运行里依次加载测量（一个期限：默认校验超时，或每份不同内容 5 秒加每个 Sprite 10 秒，取较长者），沙箱 CPU 上限随期限放宽；字效且有 `text`、`fontSize` 参数时，文字被 overflow 不是 visible 或 `contain: paint` 的祖先裁切、超出画布、单行低于 20px 或只显示了一部分（同样按文字显示最大的帧判断）就把 `fontSize` 二分缩小到放得下的最大整数字号，不低于发布的最小值且不低于 24（更小的行高算不可读）；本来放得下则不动，缩小记服务端日志，不改模板与封存源码；大于 0 的 `keywordSize` 是绝对字号，随 `fontSize` 按同一比例缩小（不低于 12、不放大），保持关键词与正文的比例；缩到最小后若只因摆放位置仍出画布（如长标题的中心贴近顶边），只在这次渲染的副本里把摆放按最短距离平移回画布内（记日志，不改保存的摆放）；仍被裁切、过小或比画布还大才以 `text_too_long` 失败，固定说明提示缩短文字；预检沙箱无法启动按 `render_failed` 失败），再在 `overlay-worker.mjs` 隔离沙箱中按请求先后（先者在下）叠成一个透明 VP9 Alpha WebM（不含音频），转存 ZOS `imv/overlay_render/{taskId}.webm`（public-read，核对大小与匿名读取）后才成功，回调体与视频合成相同的四字段，每次投递有 30 秒整体期限，非 2xx、异常（含 httpx 无法解析的地址）与放弃均写服务端日志；失败只公开稳定错误码与固定说明，渲染器输出等根因仅写服务端日志。时长：有 `audioUrl` 以 ffprobe 读取的完整音频时长（TTS）为准，否则用 `duration`，再否则取各片段的最晚结束；无摆放、引用的 Sprite 未发布、画布不一致或已知时长（`duration` 或片段最晚结束）超过 `IMV_OVERLAY_MAX_SECONDS` 时受理返回 422，`duration` 与合成接口一样只接受 JSON 有限正数；有 `audioUrl` 时读到音频时长后才校验，超限任务以 `duration_too_long` 失败；缺 ZOS 配置、ffprobe、bwrap、prlimit、taskset、Node、浏览器或字体时受理返回 503。秒转帧与模板时间轴一样半帧向后取整；起点晚于结尾的片段丢弃，超出结尾的由总长截断（保留资产完整时长，不改变其内部动画区间；单个片段不超过 `IMV_OVERLAY_MAX_SECONDS`）；任务记录在 MySQL `remotion_overlay_renders`，进程内默认最多同时渲染六个（`IMV_OVERLAY_TASK_CONCURRENCY`；远程音频探测与 ZOS 转存不占渲染名额），渲染超时 `IMV_OVERLAY_RENDER_TIMEOUT_SECONDS` 默认 1800 秒（30 分钟，不含排队、成片校验与上传；可通过环境变量覆盖），沙箱每进程 CPU 上限取超时×核数且不低于 300 秒，首次建立 Remotion 运行时即按创建时间从早到晚恢复未终态任务与待发通知（损坏记录记日志跳过；状态写入遇锁库重试三次，仍失败则保留原状态待重启重跑，不改写为失败）。任务与 IMS 合成代码、表分离，仅复用 `ZosSettings` 与 `zos.upload_public`。
