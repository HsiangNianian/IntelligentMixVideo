## 运行与存储

- 只按单实例部署：作品、任务、版本、模型窗口、待送达事件与叠加渲染任务都在共享 MySQL（8.0 及以上，`tables.py`），租约行 `remotion_instance` 保证同一数据库只有一个实例领取任务；后端不创建 SQLite 或运行锁。
- 作品属于创建它的设备：作品相关 JSON 接口必须携带 `X-IMV-Device`，其他设备的作品按不存在处理；服务端不提供作品列表。预览页、字体、参考图与产物下载按不可猜测的 ID 访问，不校验设备。
- 封存版本文件、参考图、预览包与字体文件是 `imv/remotion/` 下的对象（`object_store.py`），后端只经 SHA-256 校验的本地缓存读取；模块 `.data/` 只放任务草稿、缓存与私有审计。对象的上传、下载与删除在工作线程里执行，不放在写锁里。
- 目录读写放到工作线程，不能阻塞事件循环、SSE 或取消；取消的任务不发布版本。
- 删除会话：先持久化删除标记，取消并等待运行任务与队列收尾，再删任务草稿与审计、所有成功版本的对象与缓存（ZOS 上的对象默认保留，见 `ZOS_DELETE_OBJECTS`）、没有其他会话引用的参考图与关联 MySQL 记录；不删其他会话或已发布资产。完成或不存在返回 204；清理失败返回 503（说明为「会话数据清理未完成，请重试删除。」，根因写服务端日志 `Work deletion is incomplete`）并保留标记，供显式重试与启动恢复；删除中的读写返回 410；已有 SSE 先发无 ID 的 `work.deleted` 控制事件再关闭。
- 参考图：新图片在入队事务内校验存在、由本设备上传且不属于正在删除的会话（404/409）；作品用到的每张图记在 `remotion_work_assets`，任务记录送达删除后仍据此判断引用。回答图片记录所答 `clarifications` 序号，该条澄清也写入 `answer_images`。上传 24 小时后仍无作品或任务引用的素材由每小时清理调用 `Store.prune_assets` 回收，正在删除的会话仍引用的图留给删除流程；回收失败只记日志，不影响上传或启动。
- 单次模型请求的图片合计上限为 30 MiB，按转换为检查用 PNG 后、Base64 编码前的字节数计算；窗口参考图与末尾回看帧必须共用预算，超限在发 HTTP 前拒绝。传输上限须容纳 Base64 膨胀与文本封装，不能提前拦住合法边界。
- 公开进度存 `remotion_job_progress`，与 `job.updated` 在同一事务发布、送达后随任务清理；循环记录经 `job.round` 增量发布、逐条存 `job_rounds`，终态任务不再接受记录。
- 配置类在 `settings.py`（经 `server.remotion_templates.settings` 导入），继续复用 `config_base.CommonSettings` 读取 `server/.env`，相对数据目录和默认 `server/remotion/` 渲染资源位置不变。渲染默认值集中在这里，`.env.example` 新增的渲染项只写 CPU/内存预留比例；模型预算、超时与重试的默认值与 `.env.example` 同步。

## 隔离与渲染

- 生成的代码只在 Linux 沙箱（`bwrap`、`prlimit`、`taskset`）里运行。需要沙箱的入口在入队前检查环境，不满足返回 503 并说明原因，不留下作品或任务。`IMV_ALLOW_UNSANDBOXED_WORKER` 只在 macOS 开发时生效，且不包括 `overlay-worker.mjs`。
- 沙箱命令只在 `Renderer.command` 构造（字体目录的只读挂载与 `FONTCONFIG_FILE` 也在这里）；不在各 worker 里各自加载字体，不给沙箱开放网络或 GPU。
- `validate.check`、`effect.save` 的校验器无法启动时返回 `VALIDATION_UNAVAILABLE`；组件自身抛错是 `CODE_VALIDATION_FAILED`；`PRESET_STORE_FAILED`、`SPRITE_STORE_FAILED` 只用于存储失败。
- 排版预检、渲染与校验都经 `RenderCapacity` 按 CPU/内存准入，取消或失败时释放。分块渲染保持帧区间连续完整、动画按绝对时钟，拼接无损。
- 叠加渲染失败只公开稳定错误码与固定说明，渲染器输出等根因只写服务端日志。叠加渲染任务与 IMS 合成的代码和表分开，只复用 `ZosSettings` 与 `zos.upload_public`。
- 渲染前的排版预检只改这次渲染的副本（缩小字号、把摆放平移回画布），不改模板、保存的摆放与封存源码；仍放不下以 `text_too_long` 失败，不能输出被裁切的文字。代码或参数点名了本机未缓存的库内字体时先取回，取不到以 `font_unavailable` 失败，不回落默认字体。
- 成片排版预检的最小字号若使较小的关键词或 Preset 内部小字低于可读尺寸，而请求字号下可读，先按实际测量找到可读的字号下限，再向上查找放得下的最大字号；不能因最小字号过小而误报整段文字过长。仍放不下时公开错误码与说明保持不变，资产 ID、实例序号、字数、测量字号、采样帧和失败原因仅通过异常链留在私有诊断中，不附带正文。
- 文字排版完整性按文档顺序逐节点核对正文：每个文字节点从上一个停下的位置继续，或自身包含剩余全部正文；这样关键词的光晕、描边或回显副本在同一句里重复同一片段不会被拼成「前缀 关键词 关键词 后缀」而误报 `text_too_long`，副本是否带 `aria-hidden` 也不影响判断。缺字、乱序和真实裁切仍然失败，所有实际绘制的副本继续参与字号、裁切及位置测量；生成检查与成片预检共用同一判定。
- 成功版本的诊断接口只读：不排队、不发布、不新增表；隔离运行时不可用返回 503，不能把「未检查」报告成「无诊断」。

## 字体库

- `remotion_fonts` 只增不删，字体 ID 与家族名不变，只能修正显示名、预览条与字形；库永远不空（系统默认字体在运行时首次使用时登记）。
- 预装字体随后端包发布，安装时不联网；增删预装字体要同时更新 `font_catalog.json`、`bundled_fonts/` 与 `bundled_fonts/LICENSES.txt`，测试会核对三者一致。
- 上传字体只用有边界检查的纯 Python 读取 name 表，不解码字体，也不参与修复（修复在浏览器端，见 `client/src/features/fonts/AGENTS.md`）。受信任的系统字体由 `managed_fonts.py` 按内部名称与字重提取独立 SC 子字体，不能把整个 TTC 改名后交给浏览器。
- 受管字体优先级为配置中的 SC 子字体、随包且哈希校验的 Noto Sans SC、浏览器本地中文字体；预览、排版预检与渲染共用此顺序。合成校验发现实际字形字体不符时只切换一次到随包 SC，诊断不通过只记私有日志，不能因此阻断合成或无限重试。字体库中用户明确选择的其他家族保持原有规则。
- 生成的 `fonts.conf` 必须为 `sans-serif`、`serif`、`monospace`、`system-ui`、`cursive`、`fantasy` 声明简体中文优先家族（`fonts.SC_PREFERENCES`）：沙箱用 `LANG=C.UTF-8`、Remotion 页面语言为英文，没有这条规则时 Chrome 的中日共用汉字回退在装有 `fonts-noto-cjk` 的机器上会落到 TTC 的日文面（Noto Sans CJK JP），字效、裸 `sans-serif`/`serif` 与不在本机的家族都会显示日文字形。等宽 SC 不可用时继续回退到简体无衬线家族。通用别名使用弱绑定以保留 Chromium 无字符集查询中的拉丁字体，仅含汉字的字符集查询增加强偏好；不能对所有字符使用强别名。规则只作用于回退，不能改变拉丁字形或用户选定的中文家族。worker 侧页面语言见 `server/src/server/remotion/AGENTS.md`。
- 版本字体证据同时保存源文件指纹、实际选择的字体指纹与回退选择，并绑定随包字体和目录；预览核对与响应共用一次读取的字节。字体加载晚于预检发生回退时也记录选择；最终本地回退仍继续合成，但不能声称其字形受文件指纹验证。
- 字效的 `fontFamily`（及双栏的逐栏字体）保存时换成普通字符串（`open_font_schema`），之后的选择一律按实时字体库校验（`fonts.require_family`），不按生成时冻结的枚举。

## 生成、校验与发布

- Sprite 由 style（Agent 生成的代码与样式参数）和 content（文字、关键词，由总线每次渲染传入）组成；时长不属于 Sprite，由渲染请求决定，Agent 的规则与提示词不处理时长。
- `effect.save` 的透明度检查与 `text_fit` 只用于生成路径：用户手动改参数与已发布版本不被它们阻止，也不重新检查。
- 透明度之后再以 Sprite 可能按自身长度播放的最短（0.5 秒，15 帧；字效更短时会被定格，所以字效为 1.5 秒）与最长（120 秒，3600 帧）长度各挂载首、中、尾帧（失败后恢复预览长度再跑自定义测试），抛错以 `render_lengths` 失败交给 Executor 修复（说明长度与帧号），不新增时长相关的提示词。
- 契约违规的诊断携带行列与范围，跨行节点的终点取自节点自身的结束位置，空转判断忽略消息里的位置，同一条违规只是换了行号不算新证据。
- 工具调用与检查共用 `registry.get_tool`，执行时只在当前层可用的工具中解析。
- 生成任务默认先按合理的选择做出 Sprite，用户之后再改；真正的歧义允许提问：Outer 的 `ask`、Executor 的 `needs_input` 与 Plan 的 `ask` 都以 `needs_input` 结束任务并保留问题，用户答复后续做同一作品。已委派（或已保存）的任务仍不能以普通回答结束。字效的文字与关键词由模板每次渲染时传入，生成只需要预览用的示例文字，不为这些文案、关键词或其语言追问。
- Outer 可用 `plan` 动作把任务交给 Plan ReAct 自行设计步骤（宿主不建默认计划）；Plan 在被交付设计、步骤受阻或整批无新观察时唤醒。
- Executor 窗口开头的交接消息带上用户需求 `user_intent` 与基线（含源码，`session.task_facts`）；Outer、Plan 的快照把需求放在最前。
- 缓存命中靠前缀不变：固定系统规则与工具列表，Executor 窗口只追加，变化快照放窗口之后；超过字节或图片预算才整体压缩，保留需求、当前文件与最新交换。参考图与字体库只在窗口开头读取一次，观察图按路径追加一次。
- 编辑任务只改用户要求的部分：用 `workspace.edit` 精确替换相关代码或清单，不重排其余源码。历史组合版本先由 `restore_version_files` 静默转为完整组件和 `contract`，保留 Schema、当前默认值、嵌套参数、示例关键词与内容边界，不重跑旧组合器、不改写历史。
- 双语字效记 `bilingual: true`：一组为两行「中文\n英文」，两组为四行「中文1\n英文1\n中文2\n英文2」。宿主的 `text` 保存原文各行、`textEn` 保存对应译文各行；服务端配置、模板与合成都按 `textEn` 识别双语，不新增协议字段。四行时 `lineGap` 控制组间距，`translationGap`（0～100，默认 8）控制组内中英间距，排布作用于整组，各行独立字体、字号比例和样式。`lineStartFrames` 仍为物理行数，同组必须同帧出现，如 `[0, 0, 30, 30]`。同时开启 `two_tier`、`bilingual` 的新作品必须交付两组，组合与验收均拒绝只做第一组；生成和发布检查两种语言各有对应数量的非空默认行。编辑快照保留双语标记、译文和组内间距。普通双栏与单组双语保持兼容。总线单 Sprite 渲染没有译文，清空 `textEn`，按内容组数（一组或两组中文）组织切片，不显示发布示例英文。
- 特效以用户需求为准：文字块只含需求或参考图要求的入场、出场与循环特效，宿主和提示词都不默认补淡入淡出或其他特效；需求没提动画就不加，文字全程静止显示。
- 字效生成按需求区分基础文字与关键词外观，示例词写入清单 `text.keywords`；组件按总线注入的实际内容绘制，不把示例词或位置写死在源码里。需求未提动画时保持静止。
- Preset 库保留以前成功作品的源码，`library.search` 只读检索；复用时复制到工作区核对修改，不改不可变原件。新采纳组件整份入库，不新增角色配方。
- 字效必须声明七个关键词参数，默认全部关闭；各分类的必备参数由 `categories.py` 定义，`effect.save` 与发布都检查。参数修订（「保存配置」）还必须检查合并后的完整默认值，所有关键词选项都要保持关闭（`parameters.patch_parameters` 拒绝），否则会产生只能预览、无法保存到资产的版本；已封存版本不能直接修改，发布 422 要说明恢复关闭并保存成新版本的路径。旧版本也可以在聊天里让 Agent 修复：统一保存门禁指出默认值问题，修复时保留组件外观并恢复七个选项的关闭默认值，修复后保存的新版本即可保存。
- 发布前渲染边界样本，样本失败只记日志、照常保存（可用性优先）。覆盖发布必须保留已有可编辑参数的契约，收紧即 422、提示另存；重复保存、覆盖、预览修复与删除共用该资产的 bundle 锁。
- 资产重命名可附带字效分类 `text_category`（仅 TEXT 可选 TITLE/SUBTITLE），省略保留旧值；名称与分类在同一次 JSON 更新中保存。覆盖发布在行锁下保留最新手动分类，不改模板的文字绑定或渲染内容。
- `SpriteRenderInput` 已删除的 `effect_offset_frames`、`render_frame_count` 保留字段号，不能复用。
- 调整生成规则（如 `text` 的长度、提示词示例）不追溯已发布资产与任务快照，它们保留各自的封存 Schema；要更新资产需生成新版本。

## 自由组件字效

- 所有生成与模型编辑均写 `Effect.tsx` 与 `effect.json`，已删除路径开关与旧工具链。`imv` 只提供通用内容运行时，不增加特效配方。既有版本与资产保持可读，转换只发生在任务工作区。
- 新组件的配置参数经 `text_configuration` 生成；能安全修正的清单值自动修正并写入 `notes`。历史转换的 `contract` 保留原 Schema 与默认值，不能和 `text`/`params` 混用；两种清单都走相同的校验、预览与保存工具。
- 历史静态文字组合的 `contract.text_fit_parameters` 保留宿主原有 cue 关闭测量配置，只能来自已验收版本；内容探针使用该配置，参数探针启用实际效果并错开行起点，保留 cue 待场与行跳动检查。临时参数不改源码或默认值；已保存字体的开放字符串按当前字体库验收，不重新冻结枚举。`x-imv-group` 只是面板标签，覆盖保存忽略其变化，仍检查参数类型与取值约束。
- 编辑还原须保留当前 `keywordEffect` 开关与每行字体、字重和字号比例；清单的 `keyword_look` 记录外观能力，`keyword_enabled` 记录默认开关，关闭不移除能力。自由组件的分类门禁允许关闭的布尔默认值，旧清单中宿主补足的字体条目也须逐行还原。
- 门禁包括透明度、长度、`text_fit` 与分类检查及 `effect_contract` 的必要内容契约；参数端点采样未见变化只写入检查/保存回执的 `notes`，不阻止保存或回看图，不要求模型为清除提示而删参数、反复重试，用户查看结果后再要求调整。实际运行异常仍失败。探针只用于生成路径，手动调参与已发布版本不受它约束。预览不能缓存成发布用的验收报告。
- 自由组件的契约探针、观察图和运动基准用总线定格帧 `duration_frames // 2`。参数探针须覆盖默认关闭的条件效果，并用间隔足够的合法字号检查缩放；探针临时参数不能写回作品默认值。
- 三层 ReAct 保留：各层系统提示在任务内不变、快照作为数据另发，Outer 只拿低细节图片；Plan 设计或恢复修改任务时也拿到基线的运动事实（`base.motion`）与中间帧（`accepted_version_images`，与 Executor 共用一次渲染）。
- 运动判断以运行代码量出的事实为准（`motion_facts`，回执的 `motion`），图片只是兜底：`effect.save` 只附中间帧，用来看量不出的颜色、填充、裁切与重影；关键帧在 `preview.render` 按需给。不要把方向、顺序这类判断重新压回看图。
- 缓存约束见上文「缓存命中靠前缀不变」；自由组件另外在任务内不换工具列表，观察图按路径进窗口只发一次。初次交接与压缩后的交接、参考图都须固定在窗口开头，不能被 Provider 的预算裁剪删掉；大源码保留在工作区，通过有界的 `workspace.read` 分段读取，不能让交接消息超过上下文限制。默认计划一步完成；Plan 加的步骤才新建窗口。保存过候选后不允许再提问（`needs_input`、`ask` 被拒绝），对歧义的理解与可选方向写进最后一步汇报的 `choices`、`suggestions`，作为给用户的回复。
- 所有自由组件发布入口（含 Plan 完成与额度耗尽时的自动完成）都核对工作区未再修改、最新保存的回看证据已送达 Executor；还有额度时可继续修复，耗尽时失败，不能把旧候选当作当前结果。带 `effect` 模块的步骤保存的 Sprite 可经 `steps.<id>.outputs.sprite` 传给后续步骤。
- 采纳的自由组件由 `CatalogStore.solidify` 整份存成没有角色的 Preset（同样的画法只存一次），供之后的作品经 `library.search` 读取借用；它不是组合单元。
- 多轮：任务结束时 Outer 窗口追加结果记录（`context.OUTCOME_PREFIX`），之后各轮的参考图继续发送（总数上限 `runtime.MAX_REFERENCE_IMAGES`）；修改任务第一步先附基线现在的验收联系表，不占预览次数。

## 参数修订与预算

- Remotion 手动调参不调用模型，不重跑参数/动画语义探针；保留源码。组合版本（PR76）且基线播放器包能读取页面注入默认值（首行为 `presentation.mjs` 写入的协议声明 `/* imv-preview-protocol 1 */` 或更新的版本；生成代码与默认参数也会打进包里，只认首行，不在包内搜索标记字样）时，参数修订只做参数 Schema 校验，不进入任务队列、不启动沙箱、不重新打包（更早构建的包会继续显示编译时的默认值，这样的修订仍排队渲染并重建播放器包，之后的修订即可即时保存）：任务以运行中状态直接记录，复用基线的源码、播放器包与运行证据（`tool-validation.json` 的 `inherited_from` 指向基线），在宿主上用 `export.mjs` 只解析格式化地重写默认导出，立即封存 `source=user_parameters` 修订，预览页注入该版本自己的默认值，渲染检查留给发布时的边界抽样；更早版本仍经参数合法性、编译、预览与默认导出一致性、媒体规格及产物指纹检查后保存。发布事务必须核对代码与基线一致、参数/spec 与用户补丁一致；生成仍走完整验收。用户修订关联最近 Agent 版本，完整参数保存在任务输入，不进入模型窗口；后续任务从两份状态计算有来源的 `user_parameter_changes` 净变化，改回原值则移除，模型均据此尊重当前基线。生成成功才建立新基线，失败、回答、澄清不清除用户调整。
- Remotion 模型预算由 `server/.env` 的 `IMV_MAX_OUTPUT_TOKENS`（32000）、`IMV_MAX_TOKENS`（200000）、`IMV_MAX_MODEL_CALLS`（32）和 `IMV_MODEL_TIMEOUT_SECONDS`（240）配置；单次输出上限始终生效，仅开启预算时按剩余额度缩小，所有模型角色共用任务预算。任务与渲染超时独立配置为 600 / 180 秒；模型请求遇到连接失败、超时或 429/5xx 时按 `IMV_MODEL_RETRIES`（2）与 `IMV_MODEL_RETRY_DELAY_SECONDS`（2，指数退避、上限 30 秒）等待后重试，重试不重复计入模型调用次数，等待期间取消任务立即停止；默认值与 `.env.example` 同步，修改后重启服务。
